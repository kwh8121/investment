## Preamble — 문서 효력과 재작성 금지

1.  PRD v1.7 Final은 확정된 스펙이다. 에이전트는 `spec.md`를 새로 생성하거나 PRD를 재서술하지 않는다. `spec.md` 위치에는 PRD 원문을 그대로 둔다.
    
2.  이 프로젝트는 **개인의 비상업적·비공개 내부 사용**이다. 외부 재배포 화면, 원본 전체 공개 다운로드 기능을 만들지 않는다. (PRD 서문, §9.4, §10)
    
3.  제품 범위 밖 기능 — 신규 외부 데이터 공급자, 미국 ETF 구축, 주문·자동매매, 총수익 계산, 뉴스·LLM 투자 판단, 전향 평가 자동화 — 은 어떤 태스크에서도 추가하지 않는다. (§0, §1.2)

## Article I — 정책값·검증값·보고값의 분리 (PRD §0.1)

*   **I.1** 본문과 부록 A의 임계값·기간·배점·발행 규칙은 **정책값**이다. 초기값이며 성과가 입증된 수치가 아니다. 코드·주석·화면 어디에서도 "최적화된 값" 또는 "검증된 값"으로 표현하지 않는다.
    
*   **I.2** 소스 식별자 형식, 필드 단위, 지수 비교 가능성, 실제 호출 특성은 **검증값**이다. 검증 전에는 `CALC_APPROVED`로 승격하지 않는다.
    
*   **I.3** v1.6이 제시한 실측 건수·응답 특성은 **선행 문서 보고값**이다. 원본 대조 전에는 이번 버전에서 재검증한 결과로 표현하지 않는다.
    
*   **I.4** 정책값을 변경하면 `rule_version`을 올린다. 과거 발행·평가 결과는 덮어쓰지 않는다.
    
*   **I.5 (사람 전용)** 정책값 변경, 검증값의 `CALC_APPROVED` 승격은 에이전트가 수행하거나 ruling으로 대체할 수 없다.
    

* * *

## Article II — 필드 활성화 계약 (PRD §2.2, §2.3, §13)

*   **II.1** 필드 상태 전이는 `SPEC_CONFIRMED → COLLECTED → SEMANTICS_VALIDATED → CALC_APPROVED` 순서만 허용한다. 단계를 건너뛰지 않는다.
    
*   **II.2** 승인 기록에는 필드명·소스·단위·부호·결측 처리·검증 표본·검증자·승인 시각·적용 버전을 저장한다. 하나라도 비어 있으면 승인이 아니다.
    
*   **II.3** 계산 사용 승인이 없는 필드는 점수·필터·평가에 투입하지 않는다.
    
*   **II.4** 다음은 명시적 제외·제한 필드다. 코드에서 이를 순위·필터·분류 근거로 쓰면 헌법 위반이다.
    *   `ka40003.acc_trde_prica` — 단위 미검증, 순위·필터 제외
        
    *   `ka40002` — 상품구조 분류 근거로 사용 금지
        
    *   `ka40004.trace_idex_cd` — 현재 진단 화면 전용
        
    *   `MKTCAP` — 순자산총액 대체 금지
        
    *   `ka40004.pred_dvida`, `dvid_bf_base` — 스냅샷 저장만, 계산 사용 금지
        
    *   `stk_cls`, `drng` — 의미 승인 전 단독 분류 근거 사용 금지
        
*   **II.5** §13 미결 항목(`stk_cls`·`drng`·분배 관련 필드 의미, 휴장일 명부 이월 여부, KRX 호출 제한·이용 조건, `ka10059`·`ka10060`·`ka10014` 적용 가능성, 미국 API 환율·단위·과거 범위)은 **계산에 사용하지 않는다.** 에이전트는 이 항목을 clarify로 해소하려 시도하지 않는다. 처리 규칙은 이미 확정됐다.

## Article III — 미래정보 접근 차단 (PRD §4.4, §2.2, §4.2, §4.3)

*   **III.1** 과거 재현 실행 계정·저장소 인터페이스에서 현재 마스터 접근을 **차단**한다. 차단은 문서가 아니라 테스트로 증명한다.
    
*   **III.2** 기준일 이후 가격, 이후 상태, 현재 지수코드, 현재 명칭은 신호 계산 모듈에서 접근할 수 없다. **이후 가격은 평가 모듈만 읽는다.**
    
*   **III.3** 현재 메타데이터는 과거 재현 입력에서 사용하지 않는다. 현재 마스터로 과거 유니버스를 생성하지 않는다.
    
*   **III.4** 현재 마스터를 이용한 사후 진단 결과는 과거 순위·유니버스·평가 분모를 자동 변경하지 않는다. 과거 입력 정정은 근거와 새 `data_version`을 요구한다.
    
*   **III.5** 재현은 "수집·동결한 데이터 버전에 대한 재현"으로 정의한다. 백필 데이터가 당시 게시본과 완전히 같다고 표현하지 않는다.
    
*   **III.6** 회귀 테스트 #6("과거 재현에서 현재 마스터와 미래 가격을 읽으려 하면 실패한다")은 #6-A 현재 마스터 차단(P0-02 완료 조건)과 #6-B 미래 가격 차단(DG2.5 완료 조건)으로 나눠 증명한다. 각 조각은 해당 단계 착수 시 RED로 도입하고, GREEN이 된 이후의 모든 머지에서 GREEN을 유지한다. 도입된 테스트를 skip·xfail 처리하는 것은 헌법 위반이다.

## Article IV — 상태 분리와 결측 처리 (PRD §9.3, §3.3, §5.1)

*   **IV.1** 다음 상태 축을 **단일 enum으로 섞지 않는다.** 각 축은 별도 타입·별도 컬럼이다.
    *   필드 상태: `MISSING_FIELD`, `EMPTY_STRING`, `REAL_ZERO`, `INVALID_NUMBER`
        
    *   날짜 상태: `FETCH_FAIL`, `PARTIAL`, `TRADING`, `PUBLISH_PENDING`, `NON_TRADING`
        
    *   종목 가용성: `AVAILABLE`, `DELISTED_OR_UNAVAILABLE`, `UNMAPPED`
        
    *   계산 상태: `CALCULABLE`, `INSUFFICIENT_HISTORY`, `NOT_COMPARABLE`, `INPUT_INVALID`
        
    *   가격 확보 상태: `OBSERVED`, `NOT_MATURED`, `CENSORED_MISSING`, `CENSORED_DELISTED_OR_UNAVAILABLE`
        
    *   품질 플래그: `DISTRIBUTION_SUSPECTED`, `CORPORATE_ACTION_SUSPECTED`, `NONE`
        
*   **IV.2** 결측을 0으로 채우지 않는다. 거래량·거래대금의 진짜 0은 유효값이며 공란과 구분한다.
    
*   **IV.3** `NON_TRADING` 날짜를 가격·지표 시계열에 결측 행으로 넣지 않는다. 휴장일을 종목 결측으로 적재하지 않는다.
    
*   **IV.4** 지수 시계열 일치 그룹: 20개 값 중 하나라도 결측이면 그룹을 생성하지 않는다. 결측 해싱 금지.
    
*   **IV.5** 필요한 입력이 하나라도 없으면 "미탐지"와 구분해 `NOT_CALCULABLE` / 계산 불가로 기록한다. 누락 지표의 비중을 다른 지표에 재배분하지 않는다.
    
*   **IV.6** 빈 배열의 비공란 비율을 0%로 임의 계산하지 않는다. 빈 배열만으로 비거래일을 확정하지 않는다.

## Article V — 불변성·버전·접근 통제 (PRD §9.1, §9.4, §3.4, §7.1)

*   **V.1** 기존 발행·평가 입력은 **덮어쓰지 않는다.** 데이터 수정은 새 버전·정정 사유·영향 범위를 남긴다.
    
*   **V.2** 모든 계산 산출물에는 §9.1 공통 저장 필드를 붙인다: `instrument_id, source, source_instrument_id, observation_date, date_status, fetched_at_utc, data_version, calendar_version, rule_version, classification_version, field_approval_version, raw_sha256, input_manifest_sha256, run_id`. 단일 원본 해시 하나로 전체 계산 입력을 대표하지 않는다.
    
*   **V.3** 수동 상태 변경에는 근거·작업자·시각·이전 상태를 남긴다. 기존 발행 결과를 소급 변경하지 않는다.
    
*   **V.4** 동일 주차·규칙 버전의 중복 발행은 금지한다. 지난 발행 주차를 새 후보처럼 소급 발행하지 않는다.
    
*   **V.5** API 키·토큰은 서버에서만 관리하며 원본·로그에서 제거한다. 시크릿이 코드·테스트 픽스처·로그에 나타나면 머지 차단이다.
    
*   **V.6** 원본 응답은 날짜 상태와 관계없이 보존한다. SHA-256, 수집 시각, 변환 버전을 함께 저장한다.

## Article VI — 결정성과 재현성 (PRD P0-07, §15, 부록 A.2, A.5)

*   **VI.1** 같은 입력 manifest·달력 버전·규칙 버전에서 유니버스·지표·순위·최종 후보가 **100% 재현**되어야 한다. "거의 같다"는 실패다.
    
*   **VI.2** 퍼센타일은 `Q(x) = 100 * (rank - 1) / (n - 1)`, 동점은 평균 순위, n=1이면 50. 단독·동점 모집단에서도 결정적이어야 한다.
    
*   **VI.3** 정렬은 점수 내림차순 → 당일 거래대금 내림차순 → `ISU_CD` 오름차순. 이 순서를 바꾸거나 tie-break를 생략하지 않는다.
    
*   **VI.4** 과거 퍼센타일은 해당 과거일 모집단으로 계산해 저장한다. 현재 모집단으로 다시 계산하지 않는다.
    
*   **VI.5** 지수 해시 정규화: `ROUND_HALF_UP`, 소수점 둘째 자리, 음의 0은 0. 직렬화 형식과 해시 버전을 저장한다.
    
*   **VI.6** 수치 오차 처리·정렬 구현을 고정하고 버전 관리한다. 부동소수점 비교에 임의 tolerance를 도입하려면 헌법 개정이 필요하다.
    
*   **VI.7** P0-06 공통 선정 엔진(부록 B 상태 전이)은 UI와 과거 재현에서 **동일 코드**를 사용한다. 재현용 별도 구현을 만들지 않는다.

## Article VII — 개발 Gate와 자동 튜닝 금지 (PRD §11, §14)

*   **VII.1** 구현은 §14의 11단계 순서를 따른다. 선행 Gate를 통과하지 않고 후속 단계 코드를 머지하지 않는다.
    
*   **VII.2** Gate 통과 조건(요약):
    

| Gate | 통과 조건 |
| --- | --- |
| DG0 | 국내 가격·거래대금 정본 KRX, 문서·코드 selection source 일치, 기존 충돌 계약 폐기 |
| DG1 | 날짜 5상태·anchor 완전수신·대표 5종 대조·식별자 충돌 검사·단위 승인 |
| DG2 | 원시 구간 수집, 체크포인트, 달력 버전, 252거래일 warm-up, diff 로그 |
| DG2.5 | 미래 접근 차단, 부록 A/B 결정성, 실제 만기·검열·블록 수, 100% 재현 |
| DG3 | A2/B1 최대 3개, 교체·실패 시 처리, 불변 카드, 수작업 경계 |
| DG4 | 인증·제한·재시도·복구·지연·품질 차단·원본 보호 확인 |

*   **VII.3 (핵심)** **DG2.5 실패 시 수익률을 높이기 위해 점수·필터·임계값을 자동 튜닝하지 않는다.** 실패는 버그 수정 또는 계약 수정 후 **새** `rule_version`**으로 재실행**한다. 버그 수정과 정책 실험을 분리한다.
    
*   **VII.4** Gate 통과 판정은 사람이 한다. 에이전트는 통과 조건 체크리스트와 증거를 제출할 뿐 통과를 선언하지 않는다.
    
*   **VII.5** §12.2 필수 회귀 테스트는 PRD §14 순서상 해당 단계 착수 시 RED로 도입하고, GREEN이 된 이후의 모든 머지에서 GREEN을 유지한다. DG2.5 판정 전까지 14개 모두 GREEN이어야 한다. #6은 #6-A 현재 마스터 차단(P0-02 완료 조건)과 #6-B 미래 가격 차단(DG2.5 완료 조건)으로 나눠 증명한다. 테스트 삭제·완화는 헌법 개정 사안이다.

## Article VIII — 표현 금지 사항 (PRD §1.3, §8.2, §15)

코드 주석·화면 문구·로그·문서 어디에서도 다음을 표현하지 않는다.

*   **VIII.1** 초과 가격수익률을 신호의 선별력 입증이나 수익 보장 근거로.
    
*   **VIII.2** 가격수익률을 총수익 또는 체결 기반 매매 성과로. 거래비용·세금·슬리피지·분배금은 반영되지 않았다.
    
*   **VIII.3** 지수 시계열 일치 그룹을 동일 경제적 노출 확정값으로. 명칭은 `INDEX_SERIES_MATCH_GROUP`이다.
    
*   **VIII.4** 비중첩 블록 수를 독립 표본 수로.
    
*   **VIII.5** 분배락 의심(`DISTRIBUTION_SUSPECTED`)을 분배락 확정으로. 자동 가격 보정·분배금 역산 금지.
    
*   **VIII.6** 카드 상태명(`신규/유지/강화/약화/관찰/제외`)으로 매수·매도 지시를 생성.
    
*   **VIII.7** 산업 전망·실적 개선 문구를 관찰 카드에 자동 생성.

## Article IX — 사람 전용 결정 (Superpowers "Rulings, not stalls" 예외)

에이전트는 다음 결정을 스스로 내리거나, "합리적 기본값"으로 대체하거나, 나중에 사람이 검토할 것을 전제로 진행하지 않는다. 해당 지점에 도달하면 **작업을 멈추고 결정을 요청**한다.

1.  필드의 `CALC_APPROVED` 승격 (Art. I.5, II)
    
2.  날짜 상태의 수동 변경, 특히 `PUBLISH_PENDING → NON_TRADING` 또는 `→ PARTIAL` 확정 (§3.4)
    
3.  `theta_pp`, `epsilon_pp`, 필터 임계값, 부록 A 배점·기간, 부록 B 슬롯·교체 규칙 등 **모든 정책값 변경** (Art. I)
    
4.  `DRAFT → PUBLISHED` 승격 (§7.1)
    
5.  지수 비교 가능성(`comparable`) 승인 (§5.2)
    
6.  DG0~DG4 통과 판정 (Art. VII.4)
    
7.  헌법 개정

## Development Workflow

*   **Spec:** PRD v1.7 원문. 재작성·요약본 생성 금지.
    
*   **Plan:** Superpowers `writing-plans`로 DG 단위 플랜 작성. 각 플랜의 Global Constraints 절에 이 헌법 Article I~IX 링크를 필수 포함.
    
*   **Execute:** `using-git-worktrees` → `subagent-driven-development` → `test-driven-development` → `requesting-code-review` → `finishing-a-development-branch`.
    
*   **TDD 규칙:** §12.2의 14개 테스트를 해당 DG 착수 시 RED로 먼저 배치한다. 구현 코드보다 테스트가 먼저 커밋된다.
    
*   **Gate 검증:** DG 종료 시 Gate 문서의 §11 체크리스트로 통과 조건을, §15 추적 표로 수용기준 15개 커버리지를 대조한다. `/speckit-analyze`(PRD·DG 계획·헌법 정합성)와 `/speckit-converge`(코드 대조) 보고를 보조 자료로 연결한다. 결과는 사람에게 제출.
    
*   **DG2.5 실패 루프:** `systematic-debugging` → 원인이 버그면 수정 후 동일 `rule_version` 재실행, 원인이 계약이면 `/speckit-converge`로 새 `rule_version` 태스크 생성 → 사람 승인 → 재실행.
    
*   **브레인스토밍 억제:** 모든 세션 첫 메시지에 "스펙은 PRD v1.7로 확정, 재설계·재서술 금지" 명시.

## Governance

*   이 헌법은 PRD v1.7 Final에 종속된다. PRD가 v1.8로 개정되면 헌법도 개정 검토한다.
    
*   개정은 사람만 승인한다. 개정 시 `Constitution Version`을 올리고 변경 사유·영향 Article·PRD 근거를 기록한다.
    
*   헌법 위반이 코드 리뷰에서 발견되면 머지를 차단한다. "나중에 고치겠다"로 통과시키지 않는다.
    
*   헌법에 없는 사항은 PRD → 이 프로젝트 저장소의 기존 코드 관례 → Superpowers 기본 규칙 순으로 따른다.
