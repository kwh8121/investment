# v1.7 §12.1 보유 자료 검사 기록

> **기준 스펙:** `docs/ETF_Price_Signal_MVP_PRD_v1_7_Final.md` §12.1, §14-2<br>
> **검사일:** 2026-09-15<br>
> **상태:** 검사 완료 — 추가 조회 및 DG1 재증명 필요, Gate 판정 없음<br>
> **범위:** 보유 자료의 존재·메타데이터·추적 경로만 검사한다. 원본 bytes와 자격 증명은 열람·기록·커밋하지 않는다.

## 결론

보유 자료에는 KRX ETF 일별 원본 58건(검증)과 2건(미검증, 기준일 `20260717`·`20260817`), 키움 역사 일별 원본·결과 쌍 864건이 저장소 밖에 존재한다. KRX 원본마다 metadata 파일이 1개씩 따로 있다. 그러나 이들은 v1.7의 식별자 대조, 지수 일치 그룹, 비교 가능성·분배 의심 승인, 공란 날짜 상태를 완결하는 증거가 아니다. 따라서 어떤 필드도 `CALC_APPROVED`로 승격하지 않고, 공란 날짜를 `NON_TRADING`으로 확정하지 않으며, 기존 데이터를 v1.7 Gate 통과 증거로 재사용하지 않는다.

## 검사 방법과 보유 자료

- `.env` 파일의 존재만 확인했다. 값·키 이름·인증 정보는 읽거나 기록하지 않았다.
- 저장소 밖 원본 경로 `~/.local/share/stock-market/evidence-bundle/raw/`에서 파일명·개수·metadata만 확인했다.
- KRX 검증 원본(`krx-etf-bydd-trd-<date>.json`)은 58건, 미검증 원본(`krx-etf-bydd-trd-<date>.unvalidated.json`)은 2건이며, 원본마다 `.metadata.json` 파일이 1개씩 있다. 예를 들어 `krx-etf-bydd-trd-20260908.json.metadata.json`은 기준일 `20260908`, 1,168행, SHA-256, 수집 시각을 보존한다.
- 키움 역사 일별 원본과 결과 파일은 각각 864건이다. 이는 이전 경로의 수집 사실이며, v1.7의 KRX 정본 수집 또는 역사 유니버스 증거가 아니다.
- 기존 `docs/references/dg1-data-rights-evidence-register-2026-09-07.md`, `docs/plan/gates/DG1-data-rights.md` 및 이전 DG2 증거는 역사적 참조로만 읽었다.

## 허용되는 다음 작업과 금지 경계

- 허용: 이 결과를 입력으로 DG1/P0-01 독립 구현 계획을 작성하고, PRD §12.2 #1~5·#14의 해당 테스트를 RED로 먼저 설계한다.
- 금지: 기존 원본으로 현재 KRX 유니버스·지수 일치 그룹·분배금·날짜 상태를 자동 확정하거나, 필드를 `CALC_APPROVED`로 승격하거나, 기존 migration을 수정·삭제하는 일.
- 실제 Supabase 프로젝트·기존 migration 적용 상태는 DG0 Go의 범위 밖으로 남아 있다. DG1의 새 migration 계획 전 Owner가 읽기 전용으로 확인한다.

## 검증 경계

이 기록은 파일 존재와 metadata 감사 결과다. 외부 API 호출, 원본 값 비교, 사람 승인 또는 DG1 Gate 판정은 수행하지 않았다. 코드·Gate가 충돌하면 이 기록을 조용히 수정하지 않고 새 증거와 Gate 기록으로 정정한다.
