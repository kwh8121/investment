# ETF 가격 신호 관찰·가상 추적 MVP PRD

> **버전:** v1.3 제안안  
> **기준:** 현재 확인된 KRX·키움 API 제공 범위  
> **운영 범위:** 개인의 비상업적·비공개 내부 사용  
> **상태:** 범위 재정의안 — 기존 Gate 승인과 구현 완료 여부는 별도 유지

## 1. 제품 정의와 변경 방향

**KRX·키움에서 확보할 수 있는 ETF 가격·거래량·거래대금·NAV·기본정보를 수집하고, 가격 모멘텀과 낙폭·반등 후보를 주간 단위로 관찰하며, 선정 당시 데이터와 이후 가격 변화를 재현 가능하게 기록하는 시스템이다.**
이번 MVP는 **국내 ETF의 종가 기반 관찰 기능을 우선 구현**한다. 미국 ETF는 현재 명세에 있는 목록·일봉 API의 수집 검증을 통과하면 별도 관찰 화면에 추가한다.
산업 펀더멘털, 분배금, 과거 구성종목, 역사적 환율이 필요한 기능은 범위에서 제외한다. 외부 데이터 확보를 MVP 완료의 선행조건으로 두지 않는다.

### 1.1 기존 PRD와의 주요 변경

| 기존 v1.2 | v1.3 제안 |
| --- | --- |
| 한·미 ETF 투자 가이드 | 국내 우선 ETF 가격 신호 관찰 |
| Momentum Acceleration·Oversold Recovery | 가격 모멘텀·가격 낙폭 및 반등 |
| 산업 Thesis·Fundamental Trigger | 관측된 가격·거래량 근거와 관찰 해제 조건 |
| 투자 추천 Top 3 | **주간 관찰 후보 최대 3개** |
| 과거 적격 ETF 중 키움 거래대금 상위 30종 | **수집 기준일의 적격 국내 ETF를 KRX 거래대금으로 정렬해 최대 30종** |
| 구성종목 중복률·환노출 통제 | 가격수익률 상관계수와 가상 추적 비중 관리 |
| 원화 환산 총수익·분배금 재투자 | **상장통화 기준 가격 변화 추적** |
| 3~5년 롤링 전략 백테스트 | 현재 유니버스의 과거 가격 탐색 + 수집 시작 후 전향 검증 |
| Core 6 산업 Radar·리서치 Inbox | 가용 상품 분류를 활용한 가격 신호 확산 관찰 |
| 소액 실전 진입 Gate | 제외 |

**DG2 선정 원천을 키움에서 KRX로 변경하는 것은 이번 개정의 명시적 범위 변경이다.** 기존의 키움 거래대금 단위 문제와 과거 유니버스 확보 의존성을 줄이는 목적이다. 과거 선정 기록에는 소급 적용하지 않는다.

## 2. 목표와 비목표

### 2.1 MVP 목표

1.  국내 ETF 일별 데이터를 안정적으로 수집하고 원본·정규화 결과를 보존한다.
    
2.  동일 기준일·동일 규칙에서 같은 가격 신호와 순위를 생성한다.
    
3.  모멘텀과 낙폭·반등 후보를 구분해 최대 3개를 관찰 대상으로 기록한다.
    
4.  데이터 결측·이상치·소스 불일치가 관찰 후보 발행에 반영되도록 한다.
    
5.  후보 선정 후 1·2·4·8주 가격 변화를 추적한다.
    
6.  수집 시작 이후의 유니버스·가격·규칙을 보존해 전향 검증 기반을 만든다.
    

### 2.2 MVP 비목표

*   산업 실적·수주·수출·재고에 근거한 투자 판단
    
*   분배금을 반영한 총수익·세후수익 계산
    
*   역사적 환율을 이용한 미국 ETF의 원화 성과 계산
    
*   구성종목 중복률·기초자산 기준 환노출 분석
    
*   과거 전체 적격 유니버스를 재현한 전략 백테스트
    
*   공식 ETF 설정·환매 자금유입 분석
    
*   자동매매·실계좌 주문·실전 투자 전환
    
*   추가 외부 데이터 공급자 도입
    
*   뉴스·리서치 수집 및 LLM 기반 투자 판단

## 3. 데이터 범위와 사용 계약

### 3.1 국내 데이터

| 데이터 | 사용 소스 | 제품에서의 역할 |
| --- | --- | --- |
| 일별 OHLC·거래량·거래대금 | KRX ETF 일별매매정보 | **기준 가격·유동성·순위 산출 원천** |
| NAV·순자산총액·상장좌수 | 같은 KRX API | 규모 필터, NAV 대비 가격, 좌수 변화 표시 |
| 기초지수명·기초지수 값 | 같은 KRX API | 상품 설명, 지수 연결 보조 |
| 현재 ETF 목록·상장일 | 키움 `ka10099`, `ka10100` | 현재 마스터·상장 경과 필터 |
| ETF 전체 시세·상품정보 | 키움 `ka40004`, `ka40002` | 이름·상품 분류·추종지수 보완 |
| ETF 일별 가격·NAV·거래량 | 키움 `ka40003` | KRX와 표본 교차검증 |
| 국내 일봉·수정주가 옵션 | 키움 `ka10081` | 선택적 비교 차트·조정 여부 점검 |

**국내 공식 관찰 순위에는 KRX 거래대금을 사용한다.** 키움 `ka40003.acc_trde_prica`는 의미·단위 검증 전까지 순위와 필터 입력에서 제외한다.
NAV와 순자산총액은 별도 필드로 저장한다. 시가총액으로 순자산총액을 대체하지 않는다.

### 3.2 미국 데이터

| 데이터 | 사용 소스 | 제품에서의 역할 |
| --- | --- | --- |
| ETF·ETN 목록 | `usa10104` | 현재 관찰 목록 |
| 카테고리 | `usa10105` | 가용 분류별 탐색 |
| 이름·거래소·ETF 여부 | `usa10100` | 식별자·상품 구분 |
| 일봉 | `usa06012`, `usa20590` | USD 가격·거래량 관찰 |
| 현재 시세·거래정지 여부 | `usa20100` | 보조 상태 표시 |

미국 시장은 다음 원칙을 적용한다.

*   국내와 **화면·순위·성과를 분리**한다.
    
*   가격은 환율 미적용 상태로 수집한다.
    
*   미국 AUM·상장일·상품구조 필터는 확보된 것으로 간주하지 않는다.
    
*   명세와 실제 응답이 다른 필드, 단위가 불명확한 거래금액은 계산에서 제외한다.
    
*   미국 표본 검증 실패는 국내 MVP 출시를 차단하지 않는다.
    

### 3.3 데이터 활성화 상태

각 필드는 다음 상태를 갖는다.
`명세 확인 → 수집 확인 → 의미·단위 검증 → 계산 사용 승인`
**계산 사용 승인 상태의 필드만 필터·점수·성과에 사용한다.** API에 필드가 존재한다는 이유로 즉시 계산에 투입하지 않는다.

## 4. 유니버스와 필터

### 4.1 유니버스 정의

국내 유니버스는 **해당 기준일 KRX 응답에 포함되고, 현재 마스터와 식별자 연결이 확인된 ETF**로 구성한다.
수집 기준일마다 다음을 저장한다.

*   전체 관측 종목 목록
    
*   필터 적용 전후 종목 수
    
*   종목별 제외 사유
    
*   사용한 마스터 버전
    
*   데이터 기준일과 수집 시각
    
*   소스 간 식별자 연결 상태
    

수집 시작 이전의 전체 적격 유니버스는 보유한 것으로 간주하지 않는다.

### 4.2 국내 관찰 후보 필터

| 조건 | 초기 설정 |
| --- | --- |
| 순자산총액 | 300억원 이상 |
| 60거래일 평균 거래대금 | 5억원 이상 |
| 상장 경과 | 확인된 상장일 기준 1년 이상 |
| 가격 데이터 | 선택한 지표의 관측기간 충족 |
| 식별자 | 공식 응답 간 연결 확인 |
| 상품구조 | 레버리지·인버스 제외가 검증된 상품 |
| 데이터 상태 | 필수 입력의 품질 검사 통과 |

수치는 기존 PRD에서 가져온 초기 정책값이며, 데이터 확보 사실과 구분해 버전으로 관리한다.
레버리지·인버스 구분은 검증된 `drng`·`stk_cls` 매핑이 있을 때 적용한다. **분류가 불명확하면 전체 시세 화면에는 표시하되 관찰 후보 자동 선정에서 제외한다.** 이름만으로 상품구조를 확정하지 않는다.
상폐예정 여부는 현재 데이터로 완전하게 확인할 수 없으므로 필터 충족을 주장하지 않는다.

### 4.3 소규모 검증 표본

적격 종목을 기준일의 **KRX 거래대금 내림차순**으로 정렬해 최대 30종을 선택한다. 동점은 종목코드 오름차순으로 정렬한다.
30종 미만이면 실제 개수와 제외 사유를 표시한다. 표본 수를 채우기 위해 조건을 완화하지 않는다.

## 5. 기능 요구사항

### P0-01. 데이터 수집·상태 관리

KRX 일별 데이터를 기준 원천으로 수집하고 키움 자료를 보완·교차검증에 사용한다.
**수용 기준**

*   원본 응답, 해시, 수집 시각, 변환 버전을 저장한다.
    
*   같은 데이터의 중복 적재를 방지한다.
    
*   재시도·연속조회·토큰 만료를 처리한다.
    
*   누락값을 0으로 대체하지 않는다.
    
*   최신 관측일과 데이터 지연 상태를 표시한다.
    
*   유효한 기준일 데이터를 확보하지 못하면 후보 발행을 차단한다.
    

시장 전체 응답이 없는 날은 종목별 결측과 구분한다. 거래일 달력이 검증되지 않은 상태에서는 이를 자동으로 휴장일로 확정하지 않는다.

### P0-02. 마스터·필터 관리

현재 ETF 기본정보와 기준일별 관측 유니버스를 관리한다.
**수용 기준**

*   종목코드는 숫자 전용 형식으로 제한하지 않는다.
    
*   소스별 원본 식별자와 내부 식별자를 분리한다.
    
*   미매핑 종목은 오류 목록에 보존한다.
    
*   필터별 통과 여부와 제외 사유를 확인할 수 있다.
    
*   같은 입력과 필터 버전에서 동일 유니버스를 생성한다.
    

### P0-03. 가격 기반 지표 계산

다음 지표를 자체 계산한다.
| 지표군 | 계산 항목 |
| --- | --- |
| 가격 변화 | 1·3·6개월 가격수익률 |
| 모멘텀 | 기간별 수익률 퍼센타일, 전주 대비 퍼센타일 변화 |
| 추세 | 이동평균 대비 위치·기울기 |
| 낙폭 | 관측기간 고점 대비 하락률 |
| 반등 | 최근 저점 대비 상승률, 단기 가격 변화 |
| 거래 활성도 | 거래량·거래대금의 최근 평균 대비 변화 |
| 변동성 | 일간 가격수익률의 변동성 |
| 가격/NAV | 같은 기준일의 가격과 NAV 차이 |
| 가격 동행성 | 공통 관측일 기준 6개월 일간수익률 상관계수 |

1·3·6개월을 거래일 수로 구현하는 방식과 관측기간은 지표 버전에 명시한다.
**수용 기준**

*   관측기간이 부족하면 계산 불가 상태를 반환한다.
    
*   수정주가와 미수정주가를 한 시계열에 혼합하지 않는다.
    
*   API 제공 수익률은 참고값으로 별도 저장한다.
    
*   가격수익률을 총수익률로 표시하지 않는다.
    
*   순위 계산 대상과 관측기간을 확인할 수 있다.
    

### P0-04. 두 개의 가격 신호 Scanner

#### A. 가격 모멘텀

중기 가격 강도와 단기 가속을 관찰한다.

*   1·3·6개월 가격수익률 퍼센타일
    
*   전주 대비 퍼센타일 개선
    
*   이동평균 추세
    
*   거래량·거래대금 변화
    
*   변동성·단기 급등 감점
    

#### B. 가격 낙폭·반등

큰 낙폭 이후 단기 가격 움직임의 변화를 관찰한다.

*   관측기간 고점 대비 낙폭
    
*   하락 속도 둔화
    
*   단기 수익률·추세 전환
    
*   거래 활성도 변화
    
*   급변·결측 감점
    

**펀더멘털 회복이나 저평가 여부는 점수에 포함하지 않는다.**
**수용 기준**

*   두 Scanner의 점수·순위를 분리한다.
    
*   다른 Scanner의 점수를 직접 비교하지 않는다.
    
*   구성 지표·배점·퍼센타일·계산 버전을 저장한다.
    
*   수집 실패로 지표가 빠지면 남은 지표의 비중을 임의로 높이지 않는다.
    
*   후보 수와 선정 컷을 설정값으로 관리하고 고정 70점 컷은 사용하지 않는다.
    

### P0-05. 주간 관찰 후보 최대 3개

후보는 아래 Gate를 통과해야 한다.
| Gate | 확인 내용 |
| --- | --- |
| G0 데이터 | 최신성·완전성·소스 대조 |
| G1 상품·유동성 | 식별자, 규모, 거래대금, 검증된 상품구조 |
| G2 가격 신호 | 해당 Scanner의 조건 충족 |
| G3 가상 추적 위험 | 비중, 가격 상관계수, 가격 손실 단계 |

**수용 기준**

*   전체 관찰 후보는 최대 3개다.
    
*   각 후보의 Scanner 유형과 선정 근거를 표시한다.
    
*   Scanner 간 후보 배분은 운영자가 승인하고 기록한다.
    
*   후보가 부족하면 실제 개수만 발행한다.
    
*   동일 Scanner 내 교체는 2주 연속 순위 우위와 Gate 통과를 초기 규칙으로 사용한다.
    
*   발행된 기록은 수정하지 않고 정정 버전을 만든다.
    

### P0-06. 상품 분류별 가격 신호 관찰

가용한 추종지수명·카테고리를 기준으로 가격 움직임이 여러 ETF에 나타나는지 관찰한다.
**수용 기준**

*   분류의 출처와 매핑 버전을 표시한다.
    
*   미분류 종목을 별도로 유지한다.
    
*   분류별 ETF 수·상승 비율·수익률 중앙값·거래 활성도를 제공한다.
    
*   국내 추종지수 분류와 미국 카테고리를 임의로 통합하지 않는다.
    
*   산업 업황 개선·자금유입을 확인한 것으로 표현하지 않는다.
    

Core 6 산업 분류와 산업 Radar는 이번 MVP에서 제외한다.

### P0-07. 관찰 카드·주간 기록

각 후보는 다음 필드를 갖는다.
| 필드 | 내용 |
| --- | --- |
| 관측 근거 | 가격·거래량·순위 변화 |
| 관찰 강화 조건 | 추가로 충족해야 할 가격 신호 |
| 위험 조건 | 변동성 확대·유동성 저하·데이터 문제 |
| 관찰 해제 조건 | 추세 약화·순위 하락·품질 Gate 실패 |
| 상태 | 신규 / 유지 / 강화 / 관찰 / 약화 / 제외 |
| 재현 정보 | 기준일·원본 참조·지표 및 필터 버전·승인 시각 |

서술은 실제 계산값과 연결한다. 산업 전망·실적 개선을 자동 생성하지 않는다.

### P0-08. 가상 포지션 가격 추적

국내 ETF 후보를 대상으로 **가상의 진입 가격 이후 가격 변화**를 추적한다.
초기 정책은 다음과 같다.

*   기준 가상자금: 1,000만원
    
*   종목당 배정 상한: 30%
    
*   최대 종목 수: 3개
    
*   총 배정 상한: 90%
    
*   미배정 비중: 최소 10%
    
*   종목 간 6개월 가격수익률 상관계수: 0.8 이하
    
*   가격 기준 손실 단계: -8% / -10% / -15% / -20%
    

**수용 기준**

*   신호 생성에 사용한 종가로 같은 시점에 진입했다고 가정하지 않는다.
    
*   초기 가상 진입은 승인 이후 다음 유효 거래일 종가를 기준으로 한다.
    
*   진입 규칙과 가격 평가 규칙을 버전으로 저장한다.
    
*   분배금·세금·수수료·환전손익을 포함하지 않는다.
    
*   화면에는 **‘비용·분배금 미반영 가격 손익’**으로 표시한다.
    
*   미배정 금액에는 이자수익을 부여하지 않는다.
    
*   -20% 단계에서는 신규 가상 진입을 중단한다.
    
*   가격 연속성 문제가 확인되면 해당 성과 계산을 보류한다.
    

미국 ETF는 USD 단일 종목 가격 추적만 허용하며 국내 가상 포지션과 합산하지 않는다.

### P0-09. 과거 가격 탐색과 전향 검증

#### 과거 가격 탐색

현재 관찰 유니버스에 대해 확보 가능한 과거 가격으로 지표와 신호를 계산한다.
결과에는 다음을 명시한다.

*   현재 종목을 기준으로 선택한 표본
    
*   실제 데이터 시작·종료일
    
*   수정주가 적용 여부
    
*   분배금 미반영
    
*   상장폐지 종목 포함 여부 미보장
    
*   과거 적격성 미재현
    

이 결과는 **지표 동작·민감도 확인용**으로 사용한다.

#### 전향 검증

수집 시작 이후 저장한 당시 유니버스·가격·규칙을 사용해 후보와 결과를 평가한다.
**수용 기준**

*   과거 가격 탐색과 전향 검증을 화면·보고서에서 분리한다.
    
*   미래 데이터로 당시 순위를 다시 쓰지 않는다.
    
*   검증된 동일 입력에서 순위가 재현된다.
    
*   결과 비교는 동일 기간·동일 통화·동일 가격 기준을 사용한다.
    
*   필수 혼합 총수익 벤치마크는 사용하지 않는다.
    

### P0-10. 사후 평가

후보 발행 후 다음을 기록한다.

*   1·2·4·8주 가격수익률
    
*   관측기간 종가 기준 최대 상승·하락
    
*   후보 유지기간과 교체 빈도
    
*   가상 진입 규칙 준수 여부
    
*   데이터 이상으로 평가가 보류된 기간
    

오판·실패 원인은 다음으로 구분한다.
`DATA / SIGNAL / RULE / OBSERVATION`
산업 Thesis 검증 항목은 제외한다.

## 7. 데이터 품질·재현성 원칙

1.  **원본 보존:** 인증정보를 제거한 원본과 해시를 보관한다.
    
2.  **필드 단위 출처:** 마스터·가격·AUM의 출처를 각각 추적한다.
    
3.  **시간 분리:** 관측 기준일, 수집 시각, 신호 생성·승인 시각을 구분한다.
    
4.  **결측 유지:** 누락·빈 문자열·실제 0을 구분한다.
    
5.  **기준 일치:** 가격 소스 대조 시 날짜·거래 세션·조정 여부를 맞춘다.
    
6.  **급변 플래그:** 전일 대비 ±30% 이상 변화는 자동 점검 대상으로 처리한다. 이를 분할·병합으로 자동 확정하지 않는다.
    
7.  **불변 기록:** 기존 후보·평가 입력을 덮어쓰지 않는다.
    
8.  **비밀정보 보호:** API 키·토큰은 서버에서만 관리한다.
    
9.  **배포 경계:** 데이터 공개·재배포 기능을 만들지 않는다.

## 9. 성공 기준

*   같은 원본·기준일·버전에서 유니버스와 순위가 100% 재현된다.
    
*   검증되지 않은 필드는 필터·점수에 사용되지 않는다.
    
*   품질 Gate 실패 시 후보 발행이 차단된다.
    
*   관찰 후보를 억지로 3개까지 채우지 않는다.
    
*   가격수익률과 총수익률의 표시 혼동이 없다.
    
*   후보 선정부터 1·2·4·8주 평가까지 같은 식별자로 연결된다.
    
*   8~12주 운영으로 수집·발행·추적·복구의 안정성을 확인한다.
    

특정 수익 달성, 실전 자금 투입, 미국 시장 활성화는 국내 MVP 완료 조건에 포함하지 않는다.
