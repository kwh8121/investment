## 1. 제품 정의

KRX·키움에서 확보 가능한 국내 상장 ETF의 가격·거래량·거래대금·NAV·기본정보를 수집하고, 가격 모멘텀과 낙폭·반등 후보를 주간 단위로 관찰하며, 선정 당시 입력과 이후 가격 변화를 재현 가능하게 기록한다.
이번 MVP의 자동화 범위는 국내 ETF 종가 기반 수집·지표·Scanner·주간 후보·과거 재현이다. 국내 상장 해외자산 ETF도 포함할 수 있으나, 해당 상품과 기초지수의 일간 등락률 직접 비교는 별도 승인 대상이다.

### 1.1 목표

1.  원본과 정규화 데이터를 안정적으로 수집·보존한다.
    
2.  비거래일·게시 지연·부분 결측·호출 실패를 구분한다.
    
3.  같은 입력·규칙 버전에서 같은 유니버스·지표·순위를 생성한다.
    
4.  가격 모멘텀과 낙폭·반등 후보를 합계 최대 3개 기록한다.
    
5.  과거 후보의 1·2·4·8주 가격 변화를 계산한다.
    
6.  운영 이후 1·2·4·8주 추적은 스프레드시트로 수행한다.
    
7.  과거 재현으로 파이프라인 버그와 명백한 실패를 탐지한다.
    

### 1.2 비목표

*   산업 펀더멘털·실적·수주·수출 기반 투자 판단
    
*   분배금 재투자·총수익·세후수익 계산
    
*   미국 상장 ETF 수집·관찰
    
*   역사적 환율을 이용한 원화 성과 환산
    
*   과거 구성종목·산업·통화 노출의 정밀 분석
    
*   공식 ETF 설정·환매 자금유입 분석
    
*   실계좌 주문·자동매매·실전 전환
    
*   뉴스·리서치 수집과 LLM 투자 판단
    
*   가상 포지션·전향 사후 평가의 자동화
    

### 1.3 과거 재현의 위치

과거 재현은 파이프라인 진단이다. 초과 가격수익률을 신호의 선별력 입증이나 수익 보장 근거로 표현하지 않는다. 주간 관측의 보유기간 중첩, 동일 종목 반복, 같은 기간 후보 간 상관을 함께 표시한다. 비중첩 블록 수도 독립 표본 수로 단정하지 않는다.

## 3. 날짜 상태와 거래일 달력

### 3.1 선행 문서의 실측 보고

v1.6은 2026-06-19~2026-09-10의 60개 평일 응답에서 총 69,258행, 날짜당 1,140~1,168행을 보고했다. 2026-07-17과 2026-08-17의 전 행에서 주요 값이 공란이었다고 기술했다.
두 날짜는 회귀 테스트 대상이다. 상태 확정은 실제 원본과 anchor 수신 결과를 사용한다. 휴장일 응답 명부의 직전 거래일 이월 여부는 미검증으로 유지한다.

### 3.2 검증 순서

1.  HTTP·인증·JSON 파싱 성공 여부
    
2.  응답 구조, 배열 존재, 기준일 일치, 종목 중복 검사
    
3.  anchor 조회 성공·대상 기간 수신 완전성 확인
    
4.  날짜 상태 판정
    
5.  `TRADING` 날짜에서 행별 필수값·숫자 형식·가격 관계 검사
    
6.  필드별 완전성 확인 후 해당 날짜 계산 승인
    

원본 응답은 상태와 관계없이 보존한다. `NON_TRADING`은 가격·지표 시계열에 결측 행으로 넣지 않는다.

### 3.3 판정 우선순위

| 우선순위 | 상태 | 조건·처리 |
| --- | --- | --- |
| 1 | `FETCH_FAIL` | HTTP·인증·파싱 실패. 재시도 |
| 2 | `PARTIAL` | 구조 오류, 기준일 불일치, 중복 코드, 검증된 소스 충돌. 발행 차단 |
| 3 | `TRADING` | 구조 정상, 순자산총액 비공란 비율 90% 이상, 필수 필드별 완전성 통과, 소스 충돌 없음 |
| 4 | `PUBLISH_PENDING` | 위 조건 미충족이며 게시 확인 대기 중이거나 anchor 확인 미완료. 발행 차단 |
| 5 | `NON_TRADING` | 게시 확인 대기 종료, 순자산총액 비공란 비율 5% 이하, 완전 수신한 anchor에 날짜 없음, 모순 없음 |
| 6 | `PARTIAL` | 나머지 미해결·부분 게시·소스 불일치. 수동 검토 |

이는 상태 5종의 판정 순서이며 `PARTIAL` 분기를 두 곳에서 사용한다.
**필수 필드별 완전성:** 종가·NAV·거래량·거래대금·순자산총액 각각 비공란 비율 90% 이상을 초기 정책으로 한다. 거래량·거래대금의 진짜 0은 유효값이다. 종가·NAV·순자산총액의 0은 종목 단위 오류로 검토한다. 지수 필드 결측은 해당 종목의 지수 관련 계산을 차단하며 전체 가격 수집을 차단하지 않는다.
**빈 배열:** 비공란 비율을 0%로 임의 계산하지 않는다. 게시 확인 대기 중에는 `PUBLISH_PENDING`, 종료 후에는 `PARTIAL`이다. 빈 배열만으로 비거래일을 확정하지 않는다.

### 3.4 게시 대기와 anchor 계약

*   시간대는 `Asia/Seoul`이다.
    
*   수집 초기 시도는 평일 19:00이다. 이는 프로젝트 운영 정책이며 공급자의 게시 보장 시각이 아니다.
    
*   미완료 날짜는 최초 시도 48시간 후까지 재시도한다. 이후 판정 요건이 충족되지 않으면 `PARTIAL`로 전환한다.
    
*   anchor는 `069500`의 `ka10081` 일봉을 사용한다. 고정 1회 호출을 가정하지 않고 연속조회가 끝날 때까지 대상 구간을 수신한다.
    
*   날짜 부재 판정에는 해당 날짜 전후의 거래일 레코드까지 포함한 조회 범위와 응답 완전성 증거가 필요하다. 최근 날짜라 다음 레코드를 확보하지 못하면 비거래일 확정을 유보한다.
    
*   anchor 실패·정지 의심·수신 범위 불명확 시 날짜 부재를 근거로 삼지 않는다.
    
*   anchor가 해당 날짜를 포함하는데 KRX 값이 불완전하면, 대기 중에는 `PUBLISH_PENDING`, 대기 종료 후에는 `PARTIAL`이다.
    
*   수동 변경에는 근거·작업자·시각·이전 상태를 남긴다. 기존 발행 결과를 소급 변경하지 않는다.
    

### 3.5 거래일 달력

승인된 `TRADING` 날짜만 계산 축으로 사용한다. unresolved 날짜를 휴장일처럼 건너뛰어 수익률 구간을 압축하지 않는다. 미해결 날짜가 필요한 계산 구간에 있으면 해당 계산과 발행을 차단한다.
달력 버전, 날짜 상태, 비공란 비율, anchor 수신 범위, 판정 근거를 저장한다. anchor 대조에서 불일치가 발견되면 해당 날짜를 재검토하고 영향받는 결과는 정정 버전으로 생성한다.

## 4. 식별자·유니버스·필터

### 4.1 식별자

*   원본 관측 키는 `(BAS_DD, ISU_CD)`다.
    
*   내부 불변 키 `instrument_id`와 소스 원본 코드를 분리한다.
    
*   ticker와 원본 코드는 문자열로 저장한다. 선행 0과 영문자를 보존한다.
    
*   표준코드에 대한 임의 절삭 규칙을 사용하지 않는다. v1.6의 앞 3자리·뒤 1자리 제거 규칙은 폐기한다.
    
*   소스별 변환 함수는 명세·관측 결과로 승인한 형식만 처리한다.
    
*   보유 전체 코드에 대해 형식, 변환 성공, 변환 후 충돌, 키움 코드 일치를 검사한다.
    
*   명칭만으로 종목을 자동 합치지 않는다. 코드 변경·재사용·다대일 충돌은 수동 검토한다.
    
*   초기에는 별도 범용 매핑 테이블을 만들지 않아도 된다. 소스 연결 결과와 검증 상태는 반드시 저장한다. 예외가 확인되면 명시적 연결 테이블을 도입한다.
    

### 4.2 관측 유니버스

해당 기준일 KRX `TRADING` 응답의 ETF 집합을 `OBSERVED_UNIVERSE`로 사용한다. 현재 마스터로 과거 집합을 생성하지 않는다.
날짜별 완전성, 코드 연속성, 신규·소멸 diff, 소멸 후 성과 상태를 검증하면 `OBSERVED_UNIVERSE_VERIFIED`로 승격할 수 있다. 이 상태도 모든 생존편향과 과거 데이터 수정 영향을 제거했다는 의미는 아니다.

### 4.3 신규·소멸 감시

연속된 승인 거래일 사이의 종목 집합 diff를 기록한다. 하루 5종목 이상 소멸하면 날짜 품질 검토를 요구한다. 1~4종목 소멸도 종목별 로그를 남긴다.
과거 소멸 원인을 확인하지 못하면 `DELISTED_OR_UNAVAILABLE`로 기록한다. 현재 `ka10099`의 상태만으로 과거 상장폐지·정리매매 또는 데이터 사고를 확정하지 않는다.
현재 마스터를 활용한 사후 진단은 별도 작업에서 수행할 수 있다. 진단 결과는 과거 순위·유니버스·평가 분모를 자동 변경하지 않는다. 과거 입력 정정은 근거와 새 데이터 버전을 요구한다.

### 4.4 미래정보 접근 차단

과거 재현 실행 계정·저장소 인터페이스에서 현재 마스터 접근을 차단한다. 기준일 이후 가격, 이후 상태, 현재 지수코드, 현재 명칭은 신호 계산에 접근할 수 없다. 이후 가격은 평가 모듈만 읽는다.
역사 데이터의 관측일과 수집 시각은 별도로 보존한다. 현재 백필한 역사 데이터가 당시 게시본과 완전히 같다고 보장하지 않는다. 재현은 수집·동결한 데이터 버전에 대한 재현으로 정의한다.

검증 표본 30종으로 실제 Scanner 모집단을 제한하지 않는다.

## 5. 지수 시계열과 분배락 의심

### 5.1 지수 시계열 일치 그룹

기준일까지 공통된 최근 20거래일의 `FLUC_RT_IDX`를 십진수 방식으로 소수점 둘째 자리까지 반올림해 정규화 배열을 만들고 해싱한다. 반올림은 `ROUND_HALF_UP`, 음의 0은 0으로 통일한다. 직렬화 형식과 해시 버전을 저장한다.

*   20개 값 중 하나라도 결측이면 그룹을 생성하지 않는다.
    
*   결측을 0으로 대체하지 않는다.
    
*   날짜 배열과 단위가 같아야 한다.
    
*   해시가 같아도 정규화 배열이 같은지 추가 확인한다.
    
*   명칭은 `INDEX_SERIES_MATCH_GROUP`이다. 법적·경제적으로 동일한 지수라는 확정값이 아니다.
    
*   지수 필드가 없으면 `GROUP_UNAVAILABLE`로 표시하고 개별 후보로 다룬다. 동일 지수 중복 제거가 완전하다고 표현하지 않는다.
    
*   레버리지 여부를 지수 등락률 배수만으로 확정하지 않는다.
    

동일 Scanner의 G2 통과 종목 중 같은 그룹 대표는 당일 거래대금 최대 종목이다. 동점은 `ISU_CD` 오름차순이다. 두 Scanner를 합친 최종 목록에서도 같은 그룹은 최대 1개만 허용한다. 시계열 일치 상품 간 노출이 같다고 보장하지 않으며, 이 규칙은 초기의 보수적 반복 패턴 억제 정책이다.
지수명과 알려진 동일·상이 지수 표본으로 오병합·미병합을 검토한다. 그룹 수만으로 실효성을 판정하지 않는다. 후보 간 높은 가격 상관관계의 별도 제한은 P0 범위에서 제외한다.

### 5.2 지수 괴리의 비교 가능성

`gap_pp = ETF 일간 가격등락률(%) − 지수 일간 등락률(%)`
단위는 퍼센트포인트(pp)다. ETF 일간 가격등락률은 KRX 종가로 직접 계산한다. API `FLUC_RT`는 대조용으로 보존하며 직접 계산값과의 차이를 기록한다.
지수 통화, 환율 반영, 환헤지 구조, 평가 시점, 수익률 유형이 비교에 적합하다고 승인된 종목만 분배락 의심 규칙을 계산한다. 확인 불가 시 `NOT_COMPARABLE`이다. 지수명만으로 자동 승인하지 않는다. 이 승인은 과거 재현에서 당시 적용 가능한 근거와 유효기간을 갖춰야 한다.
TR 지수의 구성종목 배당 재투자와 ETF 자체 분배금 지급은 구분한다. TR 여부만으로 탐지식의 작동·미작동을 단정하지 않는다.

### 5.3 탐지 규칙

```
r_price_pct = 100 * (close_t / close_prev - 1)
r_nav_pct   = 100 * (nav_t / nav_prev - 1)
gap_pp      = r_price_pct - index_return_pct
nav_gap_pp  = r_nav_pct - index_return_pct

DISTRIBUTION_SUSPECTED =
    comparable
    AND gap_pp <= theta_pp
    AND nav_gap_pp <= theta_pp
    AND abs(gap_pp - nav_gap_pp) <= epsilon_pp

초기 정책: theta_pp = -0.30, epsilon_pp = 0.20
```

직전 값은 직전 승인 거래일 값이다. 필요한 입력이 하나라도 없으면 미탐지와 구분해 `NOT_CALCULABLE`로 기록한다.
이는 가격과 NAV가 지수 대비 함께 약해졌다는 이상 징후다. 분배락을 확정하지 않는다. 실제 NAV의 절대 하락만을 필수로 두지 않는다. 임계값은 탐색용 초기값이며, 실측 분포와 의심 사례의 수동 검토 결과를 기록한 후 사용 승인한다.

### 5.4 후속 처리

*   자동 가격 보정·분배금 역산은 하지 않는다.
    
*   커버드콜·월배당·인컴 계열은 `WATCH_ONLY_DISTRIBUTION`으로 표시한다. 낙폭·반등 자동 후보에서는 제외하고, 모멘텀에는 가격수익률 기준으로 포함 가능하다.
    
*   최근 20거래일에 미해결 분배락 의심이 있는 종목은 낙폭·반등 자동 후보에서 제외한다.
    
*   지수 비교 불가만으로 일반 상품을 전체 Scanner에서 제거하지 않는다. 분배락 탐지 미적용 상태를 카드에 표시한다.
    
*   모든 성과는 가격수익률로 표시한다.

## 6. 기능 요구사항 — P0 7개

### P0-01. 수집·날짜 판정·달력

원본, SHA-256, 수집 시각, 변환 버전을 보존한다. 동일 입력 중복 적재를 방지하고 토큰 만료·연속조회·재시도·날짜별 체크포인트를 처리한다. §3의 순서·상태·anchor 계약을 구현한다. 필수 날짜가 미해결이면 발행을 차단한다.

### P0-02. 마스터·유니버스·필터

원본·내부 식별자를 분리하고 변환 실패·충돌을 보존한다. 필터별 통과와 제외 사유, 신규·소멸 diff를 기록한다. 현재 마스터의 과거 접근 차단 테스트를 통과한다. 실제 계산 모집단과 검증 표본을 구분한다.

### P0-03. 가격 지표

부록 A의 기간·산식·결측·동점 규칙을 구현한다. 수정주가와 미수정주가를 혼합하지 않는다. 지표 입력이 부족하면 계산 불가를 반환한다. API 제공 수익률과 직접 계산 수익률을 분리 보관한다.

### P0-04. 분배락 의심

§5.2~5.4를 구현한다. 비교 가능성 승인, gap 단위, NAV 차이, 임계값, 플래그, 계산 불가 사유를 저장한다. 검증되지 않은 지수 비교를 강행하지 않는다. 비교 가능 종목이 없으면 탐지 기능을 `NOT_COMPARABLE`로 운영할 수 있으며, 가격 Scanner 구축을 막지 않는다.

### P0-05. 두 Scanner

A는 가격 모멘텀, B는 낙폭·반등이다. 산식·Gate·배점은 부록 A를 따른다. 두 점수를 직접 비교하지 않는다. 누락 지표의 비중을 다른 지표에 재배분하지 않는다. 점수 구성과 계산 모집단을 저장한다.

### P0-06. 주간 후보·관찰 카드

합계 최대 3개, A 2개·B 1개를 사용한다. 남는 슬롯을 다른 Scanner로 넘기지 않는다. 후보가 부족하면 실제 개수만 발행한다. 부록 B의 유지·교체·중복 규칙을 구현한다.
관찰 카드에는 종목·Scanner·순위·점수 구성·가격 근거·관찰 강화 조건·위험 조건·해제 조건·상태·그룹 상태·분배락 탐지 상태·원본 묶음 해시·버전·기준일·생성 및 승인 시각을 표시한다. 산업 전망과 실적 개선을 자동 생성하지 않는다.

### P0-07. 과거 재현·재현성 검사

§8의 백필과 평가 계약을 구현한다. 과거 신호는 기준일까지의 데이터만 사용한다. 평가 모듈만 이후 가격을 읽는다. 같은 입력에서 유니버스·지표·순위·선정 상태가 100% 재현되어야 한다. 만기 미도래·검열·분배 의심 관측을 구분한다.

## 7. 주간 운영과 수작업 경계

### 7.1 발행 일정

*   매주 월요일 09:00에 직전 월~금 구간을 평가한다. 모두 한국시간이다.
    
*   기준일은 직전 주의 마지막 승인 거래일이다.
    
*   기준일까지 필요한 날짜 중 미해결 상태가 있으면 새 후보 발행을 보류한다.
    
*   이후 매일 09:00에 재시도하고 금요일 18:00까지 미해결이면 해당 주는 `SKIPPED_DATA`로 마감한다.
    
*   다음 주에 지난 발행 주차를 새 후보처럼 소급 발행하지 않는다. 복구 결과는 진단·정정 버전으로만 남긴다.
    
*   승인 전 결과는 `DRAFT`, 승인 후 `PUBLISHED`다. 동일 주차·규칙 버전의 중복 발행은 금지한다.
    
*   승인 지연이 있어도 가격수익률 기준일은 명시적으로 보존하며, 실행 가능한 거래 체결 성과로 표시하지 않는다.
    

### 7.2 가상 포지션과 전향 평가

스프레드시트 1장에 주간 후보, 관측 기준가격, 5·10·20·40거래일 종료가격, 가격수익률, 품질 상태를 기록한다. 자동 주문·자동 잔고·자동 손실 Gate를 구현하지 않는다.
수작업 손실 단계는 개별 가상 관측의 최초 기준가격 대비 미조정 가격수익률로 정의한다.

*   -10% 이하: 해당 가상 관측을 재검토하고 수동 추가 진입을 보류한다.
    
*   -20% 이하: 신규 가상 진입을 전체 중단하고 중단 사유와 재개 승인을 기록한다.
    
*   재개는 데이터·기업행사 의심·관측 규칙을 검토한 뒤 수동 승인한다.
    

이는 초기 운영 정책이다. 자동 Scanner와 주간 후보 기록은 계속할 수 있다. P0의 G3에는 이 손실 단계를 포함하지 않는다.

## 8. 백필·과거 평가 계약

### 8.1 백필

| 항목 | 계약 |
| --- | --- |
| 원시 기간 | 2023-09-11~2026-09-10, 양끝 포함 |
| 요청일 | 기간 내 월~금 날짜를 코드로 생성 |
| 요청 수 | 생성한 날짜 목록 길이로 계산·저장. 고정 호출 수를 Gate로 사용하지 않음 |
| warm-up | 처음 252개 승인 거래일에서는 신호 미발행 |
| 평가 시작 | warm-up 이후 첫 주간 기준일 중 전체 입력을 충족하는 날짜 |
| 평가 끝 | 원시 기간 종료일까지의 실제 주간 기준일 |
| 호출 간격 | 기본 최소 1초. 서버 제한·응답 헤더 확인 시 더 보수적인 값 적용 |
| 실패 | 429·5xx는 지수 백오프. Retry-After가 있으면 우선 준수 |
| 중단 | 연속 5회 실패 시 중단. 마지막 체크포인트부터 재개 |
| 산출량 | 실제 거래일·행 수·호출 수·실행시간을 완료 후 기록 |

일일 호출 한도가 없다고 가정하지 않는다. 제한이 확인되면 날짜별 체크포인트로 여러 날에 나누어 수집한다. 3년 원시는 약 2년 평가를 목표로 하는 범위이며, 정확한 104주 또는 26개 블록을 보장하지 않는다.

### 8.2 관측 만기와 가격수익률

1·2·4·8주는 각각 기준일 이후 5·10·20·40거래일로 정의한다.

```
price_return_h = close_(t+h) / close_t - 1
```

기준일 종가 이후 생성한 관찰의 가격 변화다. 당일 종가 체결을 가정한 매매 성과로 표현하지 않는다. 거래비용·세금·슬리피지·분배금은 반영하지 않는다.

### 8.3 비교 유니버스

비교 집합은 후보 선정일의 §4.5 공통 적격 유니버스로 고정한다. Scanner별 G2, 상위 30종 검증 표본, 해시 대표 필터는 비교 집합에 적용하지 않는다. 이후 구성 변화로 과거 비교 집합을 다시 쓰지 않는다.

*   주차별 초과 가격수익률: 해당 주차 후보 수익률 중앙값 − 같은 기준일 비교 집합 수익률 중앙값.
    
*   후보별 초과 여부: 해당 후보 수익률 − 같은 기준일 비교 집합 중앙값이 0보다 큰지.
    
*   여러 주차의 요약은 주차별 초과값의 중앙값을 사용한다. 개별 후보 비율은 별도로 표시한다.
    
*   비교 집합의 만기별 가격 확보율이 90% 미만이면 해당 주차 초과수익 요약을 중단하고 `BENCHMARK_INCOMPLETE`로 기록한다.
    

확보율 90%는 초기 품질 정책이다. 남은 미확보 종목 때문에 편향이 사라졌다고 주장하지 않는다.

### 8.4 평가 상태와 검열

평가 상태를 다음 두 축으로 저장한다.
**가격 확보 상태**

*   `OBSERVED`: 종료가격 확보.
    
*   `NOT_MATURED`: 데이터 종료일까지 평가 만기가 아직 도래하지 않음.
    
*   `CENSORED_MISSING`: 만기는 도래했으나 필요한 가격 결측.
    
*   `CENSORED_DELISTED_OR_UNAVAILABLE`: 소멸·상폐 의심 등으로 종료가격 미확보.
    

**품질 플래그**

*   `DISTRIBUTION_SUSPECTED`
    
*   `CORPORATE_ACTION_SUSPECTED`
    
*   `NONE`
    

분배락 의심은 가격 확보 상태와 구분한다. 종료가격이 있으면 가격수익률은 그대로 기록하고 전체 집계에 포함한다. 의심 건 제외 결과는 별도 민감도 표로 병기하며 제외 건수를 공개한다. 미해결 기업행사 급변은 수익률을 진단용으로 보존하되 주 요약에서는 제외하고 제외 분모를 표시한다.

### 8.5 표본과 비중첩 블록

전체 주간 발행 건수·후보 건수·평가 가능 건수를 먼저 기록한다. 4주 비중첩 진단은 고정된 최초 평가 기준일부터 시작하여, 직전 선택 블록의 20거래일 종료일 이상인 첫 주간 기준일을 다음 블록으로 삼는다. 수익률 관측 구간이 겹치지 않도록 한다. 후보가 없거나 데이터가 불완전한 블록도 로그에 남긴다.
실제 성숙 블록 수, 후보 관측 수, 동일 종목 반복, 검열·제외·만기 미도래 건수를 별도로 출력한다. 블록 시작점은 결과를 본 후 바꾸지 않는다. 다른 시작점 분석은 별도 진단 버전으로만 실행한다.

### 8.6 기록 항목

*   5·10·20·40거래일 가격수익률과 평가 상태
    
*   주차별 20거래일 초과 가격수익률과 후보별 양의 초과 비율
    
*   Scanner별·전체 결과
    
*   발행 수·후보 수·비중첩 블록 수·유효 분모
    
*   비교 집합 확보율과 미확보 종목
    
*   분배락·기업행사 의심 포함 및 제외 결과
    
*   동일 종목 반복 수·교체율·발행 보류·건너뛴 주차

## 9. 데이터 계약·보안·재현성

### 9.1 공통 저장 필드

```
instrument_id

date_status
fetched_at_utc
data_version

```

여러 날짜·소스가 입력이면 원본 해시 목록과 입력 manifest를 함께 저장한다. 단일 원본 해시 하나로 전체 계산 입력을 대표하지 않는다.

### 9.2 가격과 숫자

키움 가격 문자열 부호는 필드별 계약에 따라 방향과 가격값을 분리한다. 모든 숫자 필드에 일괄 절댓값을 적용하지 않는다. 등락률·대비값의 음수는 보존한다. 원본 문자열을 함께 저장한다.
KRX OHLC는 동일한 미수정 가격 계열로 계산한다. 조정 가격은 소스 대조용 별도 계열이다. 기업행사 의심을 자동으로 분할·병합으로 확정하거나 가격을 보정하지 않는다.

### 9.3 상태 분리

*   필드 상태: `MISSING_FIELD`, `EMPTY_STRING`, `REAL_ZERO`, `INVALID_NUMBER`.
    
*   날짜 상태: §3의 5종.
    
*   종목 가용성: `AVAILABLE`, `DELISTED_OR_UNAVAILABLE`, `UNMAPPED`.
    
*   계산 상태: `CALCULABLE`, `INSUFFICIENT_HISTORY`, `NOT_COMPARABLE`, `INPUT_INVALID`.
    
*   평가 상태·품질 플래그: §8.4.
    

상태를 단일 enum으로 섞지 않는다. 결측을 0으로 채우거나 휴장일을 종목 결측으로 적재하지 않는다.

### 9.4 불변성과 접근 통제

기존 발행·평가 입력은 덮어쓰지 않는다. 데이터 수정은 새 버전·정정 사유·영향 범위를 남긴다. 신호 모듈의 미래 데이터 접근과 현재 마스터 접근을 테스트로 차단한다.
API 키·토큰은 서버에서만 관리하며 원본·로그에서 제거한다. 비공개 인증을 적용하고 외부 재배포 화면을 만들지 않는다. 개인 비공개 사용이라는 운영 범위만으로 공급자 약관 준수가 보장된다고 가정하지 않으며, 운영 전 이용 조건과 보관·호출 제한을 확인한다.

## 12. 착수 전 검증과 최소 테스트

### 12.1 보유 자료 우선 확인

| 확인 | 합격 기준 | 실패 처리 |
| --- | --- | --- |
| 전체 식별자 | 승인된 형식, 변환 충돌 없음, 대조 표본 연결 성공 | 미매핑 보존·자동 연결 보류 |
| 지수 일치 그룹 | 결측 해싱 없음, 알려진 동일·상이 표본 검토 | 그룹 규칙 비활성화 또는 수정 버전 |
| 지수 비교·분배 의심 | 비교 가능성 승인, 단위 일치, 사례 검토 | 해당 종목 `NOT_COMPARABLE` |
| 선행 실측 공란 날짜 | 원본·anchor·상태 판정 증거 일치 | 상태 미확정·발행 차단 |

보유 자료만으로 끝나는 검사를 먼저 한다. 필요한 anchor·코드 대조 자료가 없으면 추가 조회한다. 신규 호출 0회를 강제하지 않는다.

### 12.2 필수 회귀 테스트

1.  게시 전 KRX·anchor 동시 부재가 비거래일로 조기 확정되지 않는다.
    
2.  anchor 연속조회 일부만 받은 상태에서 날짜 부재를 확정하지 않는다.
    
3.  빈 배열·중복 코드·기준일 불일치를 정상 거래일로 처리하지 않는다.
    
4.  거래대금 0과 공란을 구분한다.
    
5.  식별자 선행 0·영문자·변환 충돌을 보존한다.
    
6.  과거 재현에서 현재 마스터와 미래 가격을 읽으려 하면 실패한다.
    
7.  결측 지수 배열로 그룹을 만들지 않는다.
    
8.  단독·동점 모집단의 퍼센타일이 결정적이다.
    
9.  Gate 실패 기존 후보를 교체 대기 없이 제거한다.
    
10.  두 Scanner에 같은 종목·그룹이 나와도 최종 목록에 중복되지 않는다.
     
11.  만기 미도래를 검열로 집계하지 않는다.
     
12.  소멸·분배 의심·기업행사 의심의 분모와 플래그를 유지한다.
     
13.  같은 입력 manifest와 규칙 버전에서 결과가 일치한다.
     
14.  수집 중단 후 완료 날짜를 재적재하지 않고 재개한다.

## 15. 최종 수용 기준

*   같은 입력 manifest·달력·규칙 버전에서 유니버스·지표·순위·최종 후보가 재현된다.

*   지수 일치 그룹을 동일 경제적 노출 확정값으로 표현하지 않는다.
    
*   계산 미승인 필드는 점수·필터·평가에 투입하지 않는다.

*   Gate 실패 후보는 2주 교체 대기 규칙과 무관하게 제거한다.
    
*   가격수익률을 총수익 또는 체결 기반 매매 성과로 표시하지 않는다.
    
*   분배락 의심에 자동 가격 보정을 하지 않는다.
    
*   평가 만기 미도래·검열·품질 제외와 모든 집계 분모를 구분한다.
    
*   평가 기간·발행 수·비중첩 블록 수를 실제 데이터로 산출한다.
    
*   가상 손실 단계는 수작업이며 자동 발행 Gate와 분리한다.
    
*   과거 재현 결과로 수익 보장·신호 선별력 입증을 주장하지 않는다.

## 부록 A. 지표와 Scanner 초기 규칙 — rules_v1

### A.1 공통 정의

`t-k`는 승인 거래일 달력상 k거래일 전이다. 가격은 KRX 종가다. 수익률은 내부에서 소수로 저장하며 화면에서 %로 표시한다. 지수 괴리만 pp를 사용한다.
| 지표 | 산식 |
| --- | --- |
| R5, R20, R60, R120 | `close_t / close_(t-k) - 1` |
| 1·3·6개월 | 각각 R20·R60·R120 |
| MA20, MA60 | 기준일 포함 최근 20·60거래일 종가 산술평균 |
| MA20 기울기 | `MA20_t / MA20_(t-5) - 1` |
| DD120 | `close_t / max(close_(t-119)...close_t) - 1` |
| REB20 | `close_t / min(close_(t-19)...close_t) - 1` |
| ACT20 | 최근 5거래일 평균 거래대금 / 그 직전 20거래일 평균 거래대금 |
| VOL20 | 최근 20개 일간 단순수익률의 표본 표준편차, ddof=1, 비연율화 |
| PREMIUM | `close_t / nav_t - 1` |
| MOM_CHANGE | 현재 R20 퍼센타일 − 5거래일 전 당시 모집단의 R20 퍼센타일 |

거래 활성도 분모가 0이면 계산 불가다. 필요한 입력 결측은 해당 지표 계산 불가다. R120에는 최소 121개 종가가 필요하다. 252거래일 연속 관측 필터와 별개로 모든 추가 입력을 검사한다.

### A.2 퍼센타일

Scanner별 기본 모집단을 먼저 고정한다. A는 공통 적격 유니버스 중 필요한 지표가 모두 계산 가능한 종목, B는 여기에 분배 영향 상품·최근 분배 의심 제외를 적용한 집합이다. G2 이전 모집단에서 구성 지표 퍼센타일을 계산한다.
오름차순 평균 순위를 `rank`라고 할 때 `Q(x) = 100 * (rank - 1) / (n - 1)`이다. 동점은 평균 순위, n=1이면 50이다. 과거 퍼센타일은 해당 과거일 모집단으로 계산해 저장한다. 현재 모집단으로 다시 계산하지 않는다. 필요한 과거 퍼센타일이 없으면 해당 점수는 계산 불가다.
점수 비교는 반올림 전 값을 사용한다. 표시만 소수점 둘째 자리로 한다. 수치 오차 처리·정렬 구현을 고정하고 버전 관리한다.

### A.3 A — 가격 모멘텀

```
score_A =
  0.40 * Q(R120)
+ 0.25 * Q(R60)
+ 0.15 * Q(R20)
+ 0.10 * Q(MOM_CHANGE)
+ 0.10 * Q(ACT20)
- 0.10 * Q(VOL20)
- 0.10 * Q(max(R5, 0))
```

G2 조건: `R60 > 0`, `R120 > 0`, `close_t > MA60`, `MA20_t > MA20_(t-5)`, 기본 모집단 내 score_A 퍼센타일 70 이상. 점수 자체의 절대 컷은 사용하지 않는다.

### A.4 B — 가격 낙폭·반등

```
score_B =
  0.30 * Q(-DD120)
+ 0.25 * Q(R5)
+ 0.20 * Q(REB20)
+ 0.15 * Q(ACT20)
+ 0.10 * Q(R20_t - R20_(t-5))
- 0.10 * Q(VOL20)
```

G2 조건: `-0.40 <= DD120 <= -0.10`, `R5 > 0`, `R20_t >= R20_(t-5)`, `close_t >= MA20`, 기본 모집단 내 score_B 퍼센타일 70 이상.
급변·필수 결측은 점수 감점으로 통과시키지 않고 공통 Gate에서 제외한다. 펀더멘털 회복·저평가 판단은 포함하지 않는다.

### A.5 정렬과 설정 변경

G2 통과 후 §5.1 그룹 대표를 선택한다. 각 Scanner 순서는 점수 내림차순 → 당일 거래대금 내림차순 → `ISU_CD` 오름차순이다.
모든 수치·배점은 구현을 위한 초기 정책이다. 성과 최적화를 거친 값으로 표현하지 않는다. 변경 시 규칙 버전을 올리고 기존 결과와 분리한다.

## 부록 B. 최종 후보·유지·교체 상태 전이

### B.1 Gate와 슬롯

`G0 데이터 → G1 상품·유동성 → G2 Scanner 조건 → G3 종목·시계열 일치 그룹 중복`
A에 2개, B에 1개 슬롯을 둔다. A 선정 후 B를 선정한다. B는 A와 동일 종목·그룹을 제외한 목록을 사용한다. 빈 슬롯은 서로 넘기지 않는다. 첫 발행에는 남은 순위 상위부터 채운다.

### B.2 기존 후보 처리

매주 이전 발행 후보를 먼저 재검사한다. G0 실패로 주 전체 데이터가 불완전하면 발행 보류다. 종목별 G1·G2 실패 또는 그룹 대표 자격 상실이면 해당 후보를 즉시 제외한다. 같은 주에 적격 대기 후보로 빈 슬롯을 채울 수 있다.
적격 기존 후보는 유지한다. A의 유지 후보는 최대 2개, B는 최대 1개다. 신규 상장·신규 적격 후보도 동일한 입력 요건을 충족해야 한다.

### B.3 순위 교체

빈 슬롯 충원 후에도 남는 외부 후보 중 최상위 후보를 도전자로 정한다. A에서는 유지 후보 중 순위가 가장 낮은 후보, B에서는 단일 유지 후보를 비교 대상으로 한다.
같은 도전자가 같은 비교 대상보다 2회 연속 주간 발행 평가에서 앞서고 모든 Gate를 통과하면 두 번째 평가에서 교체한다. 동점은 A.5 정렬로 판정한다. 도전자·비교 대상 변경, 발행 보류·건너뛰기, Gate 실패 시 연속 횟수는 초기화한다. Scanner당 주간 순위 교체는 최대 1건이다. Gate 실패 제외와 빈 슬롯 충원은 이 제한에 포함하지 않는다.
예: W0에 기존 후보 발행 → W1 도전자 첫 우위 → W2 같은 도전자 두 번째 우위 확인 후 교체. 고정된 3주 보유기간 또는 3주 교체 주기로 표현하지 않는다.

### B.4 A/B 중복

A 확정 후 동일 종목·그룹이 B 기존 후보에 있으면 B에서 제외한다. B의 다음 적격 후보로 슬롯을 채울 수 있다. 소스 Scanner 변경과 중복 제외 사유를 기록한다. A/B 점수를 직접 비교하지 않는다.

### B.5 카드 상태

*   `신규`: 이번에 처음 슬롯에 진입.
    
*   `유지`: 계속 선정되며 순위가 동일.
    
*   `강화`: 계속 선정되며 해당 Scanner 순위가 개선.
    
*   `약화`: 계속 선정되며 해당 Scanner 순위가 하락.
    
*   `관찰`: 적격 대기 후보 또는 수동 관찰 목록. 최종 3개에 포함하지 않음.
    
*   `제외`: Gate 실패·순위 교체·중복 등으로 슬롯 이탈.
    

가격 변화, 순위 변화, 상태 전이는 별도 필드로 저장한다. 상태명만으로 투자 매수·매도 지시를 생성하지 않는다.
