# ETF Price Signal MVP PRD v1.3 → v1.4 패치

> **작성일:** 2026-09-11
> **근거:** KRX `etf_bydd_trd` 60 평일 실측(2026-06-19~2026-09-10), 키움 REST API 명세 직접 확인
> **성격:** v1.3 조항별 개정안. 원본 PRD 파일은 변경하지 않는다.

## 0. 실측 결과 요약

| 항목 | 결과 |
|---|---|
| 호출 | 60회 연속, rate-limit·HTTP 거절 없음. 한도 부재는 미증명 |
| 응답 | 총 69,258행, 날짜당 1,140~1,168행. `BAS_DD` 일치, 날짜 내 `ISU_CD` 중복 없음 |
| 값 공란 | 2026-07-17, 2026-08-17 두 날짜의 전 행(2,309행)에서 `TDD_CLSPRC`·`NAV`·`ACC_TRDVOL`·`ACC_TRDVAL`·`INVSTASST_NETASST_TOTAMT` 모두 공란 |

**해석:** 두 날짜는 KRX 휴장일이다. 2026-08-17은 광복절 대체공휴일(8/15 토요일), 2026-07-17은 18년 만에 공휴일로 부활한 제헌절이다. 60 평일 = 거래일 58일 + 휴장일 2일.

**결론:** 데이터 결함이 아니다. 3년 백필 계획은 유지한다. 수정 대상은 백필 범위가 아니라 거래일 판정 규칙이다.

**휴장일 응답의 형태:** 행 명부는 존재하고 값 필드만 비어 있다. 행 수가 평균과 같으므로 직전 거래일 명부가 그대로 실려 있을 가능성이 높다(미검증).

## 1. §P0-01 개정 — 거래일 판정 규칙 신설

### 삭제

> 시장 전체 응답이 없는 날은 종목별 결측과 구분한다. 거래일 달력이 검증되지 않은 상태에서는 이를 자동으로 휴장일로 확정하지 않는다.

이 문구는 "응답이 없는 날"을 가정한다. 실제 휴장일은 응답도 있고 행 수도 정상이고 `BAS_DD`도 일치한다. v1.3의 검증 6개(날짜 형식, HTTP 성공, `OutBlock_1` 존재, `BAS_DD` 일치, 필수 필드 누락, 중복 행)를 전부 통과한다.

### 신설 — 날짜 상태 판정

기준일 응답마다 다음 상태 하나를 부여하고 저장한다.

| 상태 | 판정 조건 | 처리 |
|---|---|---|
| `TRADING` | `INVSTASST_NETASST_TOTAMT` 비공란 비율 ≥ 90% | 시계열에 편입 |
| `NON_TRADING` | 비공란 비율 ≤ 5% | 시계열 축에서 제외. 결측 행으로도 적재하지 않는다 |
| `PARTIAL` | 5% 초과 90% 미만 | 적재 보류, 수동 검토 |
| `FETCH_FAIL` | HTTP/JSON 실패 | 재시도 큐 |

판정 필드로 순자산총액을 쓰는 이유는 거래량 0인 ETF가 실제로 존재해 `ACC_TRDVAL`은 진짜 0과 공란을 구분해야 하지만, 순자산총액은 상장 상태라면 거래일에 항상 값이 있어야 하기 때문이다. 실측에서 0%와 100%로 완전히 갈렸으므로 90/5 임계는 여유가 크다.

`NON_TRADING`을 결측으로 적재하지 않고 축에서 제외하는 것이 핵심이다. 결측으로 넣으면 §7-4의 종목 단위 결측 규칙에 걸려 데이터 사고로 오분류된다.

### 신설 — 검증 순서 (v1.3 미규정, 이번 실측에서 드러난 결함)

파이프라인은 반드시 다음 순서로 실행한다.

```
1. HTTP/JSON 성공 여부
2. OutBlock_1 존재, BAS_DD 일치, ISU_CD 중복 없음   ← 구조 검증
3. 날짜 상태 판정 (TRADING / NON_TRADING / PARTIAL)  ← 여기서 분기
4. TRADING인 경우에만 행 단위 필수 필드·숫자 형식 검증
```

행 검증이 3번보다 먼저 돌면 휴장일마다 1,155건 전후의 행 오류가 발생하고 재시도 큐를 영구 오염시킨다. 현재 `krx-etf-daily-market-data.ts`는 이 순서를 갖고 있지 않다.

## 2. 신설 P0 — 거래일 달력 산출

외부 휴장일 달력을 도입하지 않는다. 백필 과정에서 `NON_TRADING` 날짜를 누적하면 2010-01-04 이후 전체 거래일 달력이 부산물로 생성된다.

**수용 기준**

- 날짜별 상태와 판정에 사용한 비공란 비율을 저장한다.
- §P0-03의 "1·3·6개월을 거래일 수로 구현"은 이 달력을 유일한 기준으로 사용한다.
- 독립 소스 대조: 키움 `ka10081`로 069500(KODEX 200)의 동일 구간 일봉을 조회해, `NON_TRADING`으로 판정한 날짜가 응답에 없는지 확인한다. 호출 1회로 끝난다.
- 대조 불일치 날짜는 `PARTIAL`로 강등하고 수동 검토한다.

## 4. §4.1 개정 — 과거 유니버스 복원

### 삭제

> 수집 시작 이전의 전체 적격 유니버스는 보유한 것으로 간주하지 않는다.

### 신설

KRX `etf_bydd_trd`는 `basDd` 단일 파라미터로 해당 기준일의 전종목 행을 반환하며 2010-01-04부터 제공된다. 응답 필드에 `TDD_OPNPRC/HGPRC/LWPRC/CLSPRC`, `NAV`, `ACC_TRDVOL`, `ACC_TRDVAL`, `MKTCAP`, `INVSTASST_NETASST_TOTAMT`, `LIST_SHRS`, `IDX_IND_NM`가 포함된다.

따라서 `TRADING` 날짜를 순회하면 그 시점에 실제 상장돼 있던 ETF 집합이 그대로 복원되며, 이후 상장폐지된 종목도 당시 응답에 포함되므로 생존편향이 자동 제거된다. §4.2의 순자산총액·60거래일 평균 거래대금 필터도 이 응답만으로 과거 시점에서 계산된다.

**남는 한계 (그대로 명시 유지)**

1. 분배금 미제공 → 가격수익률 한정. 총수익률 아님
2. 과거 시점의 레버리지·인버스 분류 없음 → 종목명 규칙 + 현재 `ka40004` 대조로 근사
3. 2010-01-04 이전 상장분은 상장일 미상 → "1년 경과 충족"으로만 처리

### 유니버스 diff 감시 (historical master 대조 대체)

행 수가 상장 종목 수와 일치한다는 증명은 추구하지 않는다. 그 master를 만드는 것이 원래 풀려는 문제다. 대신 불변식 2개를 쓴다.

- 연속 `TRADING` 날짜 간 종목 집합 diff를 기록한다. 신규 추가는 제한하지 않되, **하루 5종목 이상 소멸 시 플래그**한다.
- 소멸 종목은 키움 `ka10099`의 `state`, `orderWarning=2`(정리매매)와 교차 확인한다. 정리매매 이력이 없으면 데이터 사고로 처리한다.

diff는 `TRADING` 날짜끼리만 수행한다. 휴장일 응답은 직전 거래일 명부가 실려 있을 가능성이 높아 기준선으로 쓸 수 없다.

## 5. §4.2 개정 — 콜드스타트 숫자 명시

60거래일 = 캘린더 약 **88일**이다. 실측 구간 6/19~9/10은 캘린더 84일 = 거래일 58일이었다.

- 필터가 동작하려면 최소 88 캘린더일 백필이 선행되어야 한다.
- 백필 없이 수집을 시작하면 첫 약 3개월간 후보 발행이 불가능하다. v1.3에는 이 조항이 없다.

## 7. §3.1 개정 — 소스 역할 정정

| 대상 | v1.3 | v1.4 |
|---|---|---|
| KRX `etf_bydd_trd` | 기준 가격·유동성·순위 원천 | 유지 + **과거 유니버스 복원 원천**으로 승격 |
| 키움 `ka40003` | KRX와 표본 교차검증 | **교차검증 5종 한정. 확대 금지 명시** |
| 키움 `acc_trde_prica` | 의미·단위 검증 전까지 제외 | **영구 배제.** KRX `ACC_TRDVAL`로 단일화 |
| 키움 `ka40002` | 이름·**상품 분류**·추종지수 보완 | **"상품 분류" 삭제** |
| 키움 `ka10099` | 현재 ETF 목록·상장일 | 유지 + 상장경과 필터 및 정리매매 배제의 단독 원천으로 명시 |
| 미국 전체(§3.2), US-G1 | 선택 확장 | **삭제 → §10 후속 확장으로 이동** |

**근거**

- `ka40003`은 요청 파라미터가 `stk_cd` 하나뿐이고 날짜 파라미터가 없다. 과거 조회는 `cont-yn`/`next-key` 연속조회만 가능하며 종목당 별도 호출이다. 전종목 일별 시계열 확보 수단으로는 KRX보다 압도적으로 비싸다.
- `acc_trde_prica`는 명세의 단위 설명이 "단위: 1주"로 돼 있다. 누적거래대금에 주 단위 표기는 명세 오류다. 검증 비용 대비 얻는 것이 없다.
- `ka40002` 응답은 `stk_nm`, `etfobjt_idex_nm`, `wonju_pric`, `etftxon_type`, `etntxon_type`뿐이다. 상품 분류를 제공하지 않는다.
- `ka10099`는 `mrkt_tp=8: ETF`가 명세에 실재하며 `regDay`(상장일), `listCount`, `state`, `orderWarning`(2: 정리매매)를 제공한다.

### §4.2 레버리지·인버스 판별 교체

`ka40004`의 `stk_cls`, `drng`는 명세의 설명이 공란이다. "검증된 매핑이 있을 때 적용"은 무기한 보류 조건이고, 그 사이 분류 불명 종목이 전부 후보에서 빠져 스캐너가 빈다.

**교체안:** 종목명 규칙(레버리지 / 2X / 인버스 / -1X / 곱버스) 1차 판정 → `ka40004` 실측 `drng` 대조 → 불일치 건만 수동 확인.

## 8. 신설 P0 — 분배락 탐지

가격수익률만 사용하면 월배당·커버드콜 ETF가 구조적으로 왜곡된다. 분배율 연 10~15% ETF는 매달 1% 안팎 분배락이 가격에 찍히므로, 모멘텀 스캐너에서 구조적으로 감점되고 **낙폭·반등 스캐너에서는 후보로 올라온다.** §7-6의 급변 플래그는 ±30%라 이를 잡지 못한다.

**수용 기준**

- 일간 가격 하락일에 같은 날 `NAV`가 유사 비율로 동반 하락했는지 대조하고, 계단식 동반 하락은 분배락 후보로 플래그한다.
- 종목명에 월배당·커버드콜·고배당 패턴이 있는 ETF는 별도 그룹으로 표시하고 **낙폭 스캐너 자동 선정에서 제외**한다.
- 키움 `ka40004`의 `pred_dvida`(전일배당금), `dvid_bf_base`(배당전기준)를 일 1회 스냅샷 적재한다. 두 필드는 명세 설명이 공란이므로 **의미 미검증 상태로 보관만 하고 계산에 사용하지 않는다.**

## 9. P0 축소

v1.3은 P0 10개 + Gate 6개 + 화면 4개다. 1인 운영 기준으로 첫 후보 발행에 도달하지 못한다.

**P0 유지:** P0-01(수집) / P0-02(마스터·필터) / P0-03(지표) / P0-04(스캐너 2종) / P0-07(관찰 카드)
**P0 신설:** 거래일 달력(§2) / 분배락 탐지(§8)

| 항목 | v1.3 | v1.4 | 사유 |
|---|---|---|---|
| P0-06 분류별 신호 확산 | P0 | P2 | 후보 선정에 입력되지 않는 관찰 화면 |
| P0-08 가상 포지션 추적 | P0 | **코드 없음. 스프레드시트 1장** | 후보 3개, 주 1회 갱신 |
| P0-09 전향 검증 | P0 | P1 | DG2.5 부활로 우선순위 후퇴 |
| P0-10 사후 평가 | P0 | P1 | 8주 후 첫 데이터 발생 |

### 기타 조항 수정

- **§P0-03 상관계수 0.8 컷** → `ka40004`의 `trace_idex_cd` 중복 배제로 교체. 국내 ETF는 KOSPI 베타가 지배적이라 0.8 컷이 대부분의 쌍을 통과시킬 것으로 추정되며 계산도 비싸다.
- **§P0-08 손실 단계 4개(-8/-10/-15/-20%)** → -20%에만 행동 규정이 있다. 각 단계 행동을 명시하거나 -10%/-20% 2단계로 축소한다.
- **§P0-05 "2주 연속 순위 우위"** → 주간 발행에 2주 연속이면 실질 교체 주기가 3주다. 의도한 회전율인지 명시한다.
