## 1. 제품 정의

**KRX·키움에서 확보할 수 있는 국내 ETF의 가격·거래량·거래대금·NAV·기본정보를 수집하고, 가격 모멘텀과 낙폭·반등 후보를 주간 단위로 관찰하며, 선정 당시 데이터와 이후 가격 변화를 재현 가능하게 기록하는 시스템이다.**

이번 MVP는 **국내 ETF의 종가 기반 관찰 기능만 구현한다.** 미국 ETF는 API 명세 확인을 완료했으나 이번 범위에서 제외한다(§2.4).

산업 펀더멘털, 분배금, 과거 구성종목, 역사적 환율이 필요한 기능은 범위에서 제외한다. 외부 데이터 확보를 MVP 완료의 선행조건으로 두지 않는다.

### 1.1 목표

1. 국내 ETF 일별 데이터를 안정적으로 수집하고 원본·정규화 결과를 보존한다.
2. 거래일과 비거래일, 게시 지연, 부분 결측, 호출 실패를 구분한다.
3. 동일 기준일·동일 규칙에서 같은 가격 신호와 순위를 생성한다.
4. 모멘텀과 낙폭·반등 후보를 구분해 최대 3개를 관찰 대상으로 기록한다.
5. 후보 선정 후 1·2·4·8주 가격 변화를 추적한다.
6. 과거 3년 원시 데이터로 파이프라인의 명백한 실패를 걸러낸다.

### 1.2 비목표

- 산업 실적·수주·수출·재고에 근거한 투자 판단
- 분배금을 반영한 총수익·세후수익 계산
- 미국 ETF 관찰 기능 (§11로 이월)
- 역사적 환율을 이용한 원화 성과 계산
- 구성종목 중복률·기초자산 기준 환노출 분석
- 공식 ETF 설정·환매 자금유입 분석
- 자동매매·실계좌 주문·실전 투자 전환
- 추가 외부 데이터 공급자 도입
- 뉴스·리서치 수집 및 LLM 기반 투자 판단

### 1.3 백테스트의 위치

**과거 재현(DG2.5)은 신호의 선별력을 증명하는 도구가 아니라, 파이프라인 버그와 명백한 실패를 걸러내는 진단 도구다.**

2년 평가 구간에서 주간 발행·4주 보유 기준의 비중첩 블록은 26개이고, 블록당 후보 3개를 합쳐도 관측은 78건이다. 같은 블록의 3개 후보는 상호 상관되므로 실질 표본은 더 작다. 이 크기에서 나온 초과수익 수치를 성과 근거로 표현하지 않는다.

|---|---|---|---|

| 대상 | 처리 | 근거 |

### 2.3 데이터 활성화 상태

각 필드는 `명세 확인 → 수집 확인 → 의미·단위 검증 → 계산 사용 승인` 상태를 갖는다.

**계산 사용 승인 상태의 필드만 필터·점수·성과에 사용한다.** API에 필드가 존재한다는 이유로 계산에 투입하지 않는다.

### 2.4 미국 ETF — 명세 확인 완료, 구축 보류

키움 REST API 명세에서 다음이 실재함을 확인했다. 이 표는 후속 확장을 위한 자산으로 보존한다.

| 목적 | API | 확인된 주요 필드 |
|---|---|---|
| ETF·ETN 목록 | `usa10104` | `stex_tp`, `code`, `cate1`, `cate2`, `etn`, `mkgb`, `upnm` (**종목명 없음**) |
| 카테고리 사전 | `usa10105` | 1·2차 카테고리 코드·이름 |
| 개별 종목 식별 | `usa10100` | `stk_nm`, `stk_enm`, `mkgb`, `upgb`, `isEtf` |
| 조정 옵션 일봉 | `usa06012` | USD OHLC, `acc_trde_qty`, `acc_trde_prica`(**단위 미기재**), `dt`, `upd_stkpc_tp`, `upd_rt`, `strt_dt`, `exrt_appl_tp` |
| 기준일 이전 일별주가 | `usa20590` | USD OHLC, `acc_trde_qty`, `trde_prica`(**단위: 천USD**), `base_pric` |
| 현재 상태 | `usa20100` | `cur_prc`, 52주 고저, `mac`(시가총액, 천USD), `trd_susp_tp`, `curr_unit`, `base_exrt` |
| ETF 순위 4종 | `usa20511`, `usa20541`, `usa20941`, `usa24111` | 기간 등락률·거래대금·누적등락률·52주 고저 대비 |

**보류 사유 (3건)**

1. **신호 가치.** `usa20541`(당일 거래대금 상위)로 파일럿 유니버스를 구성하면 상위 50종은 대형 베타 상품으로 채워지고, 레버리지·인버스 제외 후 남는 30~35종은 전부 광범위 지수형이다. 이 집합에 모멘텀·낙폭 스캐너를 돌려 얻는 정보는 파이프라인 없이도 알 수 있다.
2. **미래정보.** 현재 거래대금 순위로 유니버스를 정하고 과거 가격을 탐색하는 구조는 §4.3의 원칙을 위반한다. 국내에서 금지한 것을 미국에서 허용하면 원칙 자체가 무너진다.
3. **미확정 비용.** `usa10104`에 종목명이 없어 명칭 기반 위험상품 필터가 마스터 단계에서 불가능하다. `usa10100`을 종목당 1회 호출해야 하며 전체 확대 시 3,000콜 이상이다.

**미국에서 현재 확보 불가한 데이터:** AUM, NAV, 분배금·분배락, 구성종목·비중 이력, 법적 상장일, 과거 시점의 전체 유니버스, 검증된 레버리지·인버스 플래그, 과거 일자별 원화 환율.

## 3. 날짜 상태와 거래일 달력

### 3.1 실측 근거

60 평일(2026-06-19~2026-09-10) 수집 결과:

- 총 69,258행, 날짜당 1,140~1,168행
- `BAS_DD` 요청일 일치, 날짜 내 `ISU_CD` 중복 없음
- **2026-07-17, 2026-08-17 두 날짜의 전 행(2,309행)에서 `TDD_CLSPRC`·`NAV`·`ACC_TRDVOL`·`ACC_TRDVAL`·`INVSTASST_NETASST_TOTAMT`가 모두 공란**

두 날짜는 KRX 휴장일이다. 2026-08-17은 광복절 대체공휴일(8/15 토요일), 2026-07-17은 공휴일로 부활한 제헌절이다. 60 평일 = 거래일 58일 + 휴장일 2일.

**휴장일 응답의 형태:** 행 명부는 존재하고 값 필드만 비어 있다. 행 수가 평균과 같으므로 직전 거래일 명부가 실려 있을 가능성이 높다(미검증).

### 3.2 날짜 상태 5종

| 상태 | 판정 조건 | 처리 |
|---|---|---|
| `TRADING` | 구조 검증 통과 AND `INVSTASST_NETASST_TOTAMT` 비공란 비율 ≥ 90% | 적재·계산 |
| `NON_TRADING` | 비공란 비율 ≤ 5% AND 키움 anchor 일봉에도 해당 날짜 없음 | **시계열 축에서 제외.** 결측 행으로도 적재하지 않는다 |
| `PUBLISH_PENDING` | 거래일 가능성이 있고 게시 완료 시각 전이거나, anchor에는 날짜가 존재 | 지연 재시도 |
| `PARTIAL` | 비공란 비율 5% 초과 90% 미만, 또는 소스 불일치 | 발행 차단, 수동 검토 |
| `FETCH_FAIL` | HTTP·JSON·인증 실패 | 재시도 큐 |

판정 필드로 순자산총액을 쓰는 이유: 거래량 0인 ETF가 실재하므로 `ACC_TRDVAL`은 진짜 0과 공란을 구분해야 하지만, 순자산총액은 상장 상태라면 거래일에 항상 값이 있어야 한다. 실측에서 0%와 100%로 완전히 갈렸으므로 90/5 임계는 여유가 크다.

`NON_TRADING`을 결측으로 적재하지 않고 축에서 제외하는 것이 핵심이다. 결측으로 넣으면 §8-4의 종목 단위 결측 규칙에 걸려 데이터 사고로 오분류된다.

### 3.3 검증 순서 (필수)

```
1. HTTP/JSON 성공 여부
2. OutBlock_1 존재, BAS_DD 일치, ISU_CD 중복 없음        ← 구조 검증
3. 날짜 상태 판정 (TRADING/NON_TRADING/PUBLISH_PENDING/PARTIAL)  ← 분기
4. TRADING인 경우에만 행 단위 필수 필드·숫자 형식 검증
```

**행 검증이 3번보다 먼저 실행되면 휴장일마다 1,155건 전후의 행 오류가 발생하고 재시도 큐를 영구 오염시킨다.**

### 3.4 거래일 달력

외부 휴장일 달력을 도입하지 않는다. 백필 과정에서 `NON_TRADING` 날짜를 누적하면 거래일 달력이 부산물로 생성된다.

**수용 기준**

- 날짜별 상태와 판정에 사용한 비공란 비율을 저장한다.
- §6의 "1·3·6개월을 거래일 수로 구현"은 이 달력을 유일한 기준으로 사용한다.
- 교차검증: 키움 `ka10081`로 069500의 동일 구간 일봉을 조회해, `NON_TRADING` 판정 날짜가 응답에 없는지 확인한다. 호출 1회.
- 대조 불일치 날짜는 `PARTIAL`로 강등하고 수동 검토한다.

## 4. 유니버스와 필터

### 4.1 관측 유니버스

국내 유니버스는 **해당 기준일 KRX `TRADING` 응답에 포함된 ETF**로 구성한다. 과거 기준일에도 동일하게 적용한다.

KRX 기준일 응답은 그 날짜에 상장돼 있던 종목 집합을 제공하므로 생존편향을 크게 줄인다. 다만 다음 검증 전에는 "생존편향 자동 제거"라고 단정하지 않고 `OBSERVED_UNIVERSE` 상태로 표기한다. 검증 통과 시 `OBSERVED_UNIVERSE_VERIFIED`로 승격한다.

- 날짜별 응답 완전성
- 동일 종목의 식별자 연속성
- 신규·소멸 종목 diff
- 소멸 후 4주·8주 성과의 검열 처리

**내부 키:** `(BAS_DD, ISU_CD)`. 사용자 표시용 ticker와 교차 소스 연결은 별도 관리한다.

### 4.2 유니버스 diff 감시

행 수가 상장 종목 수와 일치한다는 증명은 추구하지 않는다. 그 master를 만드는 것이 원래 풀려는 문제다. 대신 불변식 2개를 쓴다.

- 연속 `TRADING` 날짜 간 종목 집합 diff를 기록한다. 신규 추가는 제한하지 않되 **하루 5종목 이상 소멸 시 플래그**한다.
- 소멸 종목은 키움 `ka10099`의 `state`, `orderWarning=2`(정리매매)와 교차 확인한다. 정리매매 이력이 없으면 데이터 사고로 처리한다.

diff는 `TRADING` 날짜끼리만 수행한다. 휴장일 응답은 직전 거래일 명부일 가능성이 높아 기준선으로 쓸 수 없다.

### 4.3 미래정보 금지 원칙

| 대상 | 실시간 Scanner | 과거 재현 |
|---|---|---|
| 동일 지수 판정 | `ka40004.trace_idex_cd` 사용 가능 | **해당 기준일의 `FLUC_RT_IDX` 시계열만 사용** (§5.1) |
| 상장 경과 | `ka10099.regDay` | **252거래일 연속 관측** 또는 검증된 listing source |
| 상품구조 | 현재 명칭 규칙 + `drng` 대조 | 해당 기준일의 `ISU_NM` 명칭 규칙만 |

과거 재현에 현재 시점에만 존재하는 정보를 입력하지 않는다. 예외 없다.

### 4.4 자동 후보 필터

| 조건 | 초기값 |
|---|---|
| 순자산총액 | 300억원 이상 |
| 60거래일 평균 거래대금 | 5억원 이상 |
| 상장 경과 | 현재는 `ka10099.regDay`, 과거는 252거래일 연속 관측 |
| 관측기간 | 6개월 지표에 필요한 유효 거래일 충족 |
| 상품구조 | 레버리지·인버스·정리매매 제외 |
| 데이터 | 핵심 필드와 날짜 Gate 통과 |
| 분배 영향 | 분배 영향이 큰 상품군은 낙폭·반등 자동 선정 제외 (§5.2) |

수치는 초기 정책값이며 데이터 확보 사실과 구분해 버전으로 관리한다.

**콜드스타트:** 60거래일 = 캘린더 약 88일. 필터가 동작하려면 최소 88 캘린더일의 백필이 선행되어야 한다. 백필 없이 수집을 시작하면 첫 약 3개월간 후보 발행이 불가능하다.

**레버리지·인버스 판별:** 명칭 규칙(레버리지 / 2X / 인버스 / -1X / 곱버스) 1차 판정 → `ka40004.drng` 실측 대조 → 불일치 건만 수동 확인. `stk_cls`·`drng`는 명세 설명란이 공란이므로 단독 근거로 사용하지 않는다.

분류가 불명확한 종목은 삭제하지 않고 `WATCH_ONLY_UNCLASSIFIED`로 보존한다. 전체 시세 화면에는 표시하되 자동 선정에서 제외한다.

### 4.5 검증 표본

적격 종목을 기준일의 **KRX 거래대금 내림차순**으로 정렬해 최대 30종을 선택한다. 동점은 `ISU_CD` 오름차순. 30종 미만이면 실제 개수와 제외 사유를 표시하며, 표본 수를 채우기 위해 조건을 완화하지 않는다.

## 5. 기초지수 필드 활용

KRX 응답에는 호출 비용 없이 `IDX_IND_NM`(기초지수명), `OBJ_STKPRC_IDX`(기초지수 종가), `CMPPREVDD_IDX`(기초지수 대비), `FLUC_RT_IDX`(기초지수 등락률)가 포함된다. v1.3~v1.5는 이를 사용하지 않았다.

### 5.1 동일 지수 중복 제거

최근 **20거래일의 `FLUC_RT_IDX` 시계열을 소수점 둘째 자리로 반올림해 해시**로 만들고, 해시가 같으면 동일 지수 그룹으로 판정한다.

- 운용사별 지수명 표기 차이를 우회한다
- **해당 기준일까지의 데이터만 사용하므로 미래정보가 원천적으로 없다** — §4.3 충족
- 상관계수 계산보다 저렴하고 판정이 이진적이다
- 레버리지 ETF는 지수 등락률이 배수로 나타나므로 배수 판정의 보조 근거가 된다

동일 그룹의 대표는 **해당 기준일 거래대금 최대 종목**으로 선택한다. 동점은 `ISU_CD` 오름차순. 선택 규칙과 동률 규칙을 저장한다.

**v1.3의 "6개월 일간수익률 상관계수 0.8 이하" 조항은 이 규칙으로 대체한다.** 착수 전 확인 항목 3(§12)의 결과에 따라 유지 여부를 최종 결정한다.

### 5.2 분배락 의심 탐지

분배락일에는 ETF 가격과 NAV는 하락하지만 가격지수형 기초지수는 하락하지 않는다.

```
gap = FLUC_RT − FLUC_RT_IDX
DISTRIBUTION_SUSPECTED :  gap ≤ θ  AND  NAV 등락률이 유사 폭으로 하락
θ 초기값 = -0.30%  (60일 실측 분포로 확정)
```

**제약 사항 (반드시 명시)**

- 총수익(TR)형 지수를 추종하는 ETF는 지수에도 분배가 반영되므로 이 식이 작동하지 않는다.
- 따라서 판정 결과는 `SUSPECTED`이며 **확정값이 아니다.**
- **자동 가격 보정을 하지 않는다.** 플래그만 부여한다.
- 분배 영향이 큰 상품군(커버드콜·월배당·인컴 계열)은 명칭 규칙으로 식별해 낙폭·반등 자동 후보에서 제외하고 `WATCH_ONLY_DISTRIBUTION`으로 표시한다.
- 분배금 원천을 확보하기 전까지 모든 성과를 **가격수익률**로 명시한다.

이 규칙이 없으면 분배율 연 10~15% 상품이 모멘텀 Scanner에서 구조적으로 감점되고, 동시에 낙폭 Scanner의 상위 후보로 자동 선정된다. v1.3 §7-6의 ±30% 급변 플래그는 1~3% 분배락을 잡지 못한다.

## 6. 기능 요구사항 (P0 7개)

### P0-01. KRX 일별 수집 · 날짜 상태 판정 · 거래일 달력

**수용 기준**

- 원본 응답, SHA-256 해시, 수집 시각, 변환 규칙 버전을 저장한다.
- 같은 데이터의 중복 적재를 방지한다.
- 재시도·연속조회·토큰 만료를 처리한다.
- 누락값을 0으로 대체하지 않는다.
- §3.3의 검증 순서를 지킨다.
- §3.2의 날짜 상태 5종을 판정해 저장한다.
- 거래일 달력을 §3.4 기준으로 산출하고 `ka10081` 1회 호출로 교차검증한다.
- `TRADING` 기준일을 확보하지 못하면 후보 발행을 차단한다.

### P0-02. 마스터 · 관측 유니버스 · 필터

**수용 기준**

- 종목코드를 숫자 전용 형식으로 제한하지 않는다.
- 소스별 원본 식별자와 내부 식별자를 분리한다.
- 미매핑 종목은 오류 목록에 보존한다.
- 필터별 통과 여부와 제외 사유를 확인할 수 있다.
- 같은 입력과 필터 버전에서 동일 유니버스를 생성한다.
- §4.2 diff 감시 로그를 남긴다.
- §4.3 미래정보 금지 원칙을 코드 레벨에서 강제한다 (과거 재현 경로에서 현재 마스터 테이블 접근 차단).

### P0-03. 가격 기반 지표 계산

| 지표군 | 계산 항목 |
|---|---|
| 가격 변화 | 1·3·6개월 가격수익률 |
| 모멘텀 | 기간별 수익률 퍼센타일, 전주 대비 퍼센타일 변화 |
| 추세 | 이동평균 대비 위치·기울기 |
| 낙폭 | 관측기간 고점 대비 하락률 |
| 반등 | 최근 저점 대비 상승률, 단기 가격 변화 |
| 거래 활성도 | 거래량·거래대금의 최근 평균 대비 변화 |
| 변동성 | 일간 가격수익률의 변동성 |
| 가격/NAV | 같은 기준일의 가격과 NAV 차이 |
| 지수 괴리 | `FLUC_RT − FLUC_RT_IDX` (분배락 판별 입력) |

**수용 기준**

- 1·3·6개월은 §3.4 거래일 달력 기준의 거래일 수로 구현하고 지표 버전에 명시한다.
- 관측기간이 부족하면 계산 불가 상태를 반환한다.
- 수정주가와 미수정주가를 한 시계열에 혼합하지 않는다.
- API 제공 수익률은 참고값으로 별도 저장한다.
- **가격수익률을 총수익률로 표시하지 않는다.**
- 순위 계산 대상과 관측기간을 확인할 수 있다.

### P0-04. 분배락 의심 탐지

§5.2의 규칙을 구현한다.

**수용 기준**

- `DISTRIBUTION_SUSPECTED` 플래그와 `gap` 값을 함께 저장한다.
- 자동 가격 보정을 수행하지 않는다.
- 분배 영향 상품군은 `WATCH_ONLY_DISTRIBUTION`으로 분류하고 낙폭·반등 자동 선정에서 제외한다.
- `ka40004.pred_dvida`·`dvid_bf_base`를 일 1회 스냅샷 적재하되 계산에 사용하지 않는다.
- θ 임계값을 설정값으로 두고 결정 근거(실측 분포)를 기록한다.

### P0-05. 두 개의 가격 신호 Scanner

**A. 가격 모멘텀** — 1·3·6개월 수익률 퍼센타일, 전주 대비 퍼센타일 개선, 이동평균 추세, 거래 활성도 변화, 변동성·단기 급등 감점

**B. 가격 낙폭·반등** — 관측기간 고점 대비 낙폭, 하락 속도 둔화, 단기 수익률·추세 전환, 거래 활성도 변화, 급변·결측 감점

**펀더멘털 회복이나 저평가 여부는 점수에 포함하지 않는다.**

**수용 기준**

- 두 Scanner의 점수·순위를 분리하고 서로 직접 비교하지 않는다.
- §5.1 동일 지수 중복 제거를 두 Scanner 모두에 적용한다.
- 구성 지표·배점·퍼센타일·계산 버전을 저장한다.
- 수집 실패로 지표가 빠지면 남은 지표의 비중을 임의로 높이지 않는다.
- 후보 수와 선정 컷을 설정값으로 관리하고 고정 점수 컷을 사용하지 않는다.

### P0-06. 주간 관찰 후보 최대 3개 · 관찰 카드

후보 Gate: `G0 데이터`(최신성·완전성·소스 대조) → `G1 상품·유동성`(식별자, 규모, 거래대금, 상품구조) → `G2 가격 신호`(해당 Scanner 조건) → `G3 중복·위험`(동일 지수 그룹 중복, 분배 영향, 손실 단계)

**관찰 카드 필드**

| 필드 | 내용 |
|---|---|
| 관측 근거 | 가격·거래량·순위 변화 |
| 관찰 강화 조건 | 추가로 충족해야 할 가격 신호 |
| 위험 조건 | 변동성 확대·유동성 저하·데이터 문제·분배락 의심 |
| 관찰 해제 조건 | 추세 약화·순위 하락·품질 Gate 실패 |
| 상태 | 신규 / 유지 / 강화 / 관찰 / 약화 / 제외 |
| 재현 정보 | 기준일·원본 해시·지표 및 필터 버전·승인 시각 |

**수용 기준**

- 전체 관찰 후보는 최대 3개. 부족하면 실제 개수만 발행한다.
- 각 후보의 Scanner 유형과 선정 근거를 표시한다.
- 동일 Scanner 내 교체는 2주 연속 순위 우위와 Gate 통과를 초기 규칙으로 한다. **이 규칙의 실질 교체 주기는 3주이며 의도된 값임을 문서에 명시한다.**
- 발행된 기록은 수정하지 않고 정정 버전을 만든다.
- 서술은 실제 계산값과 연결한다. 산업 전망·실적 개선을 자동 생성하지 않는다.

5. Scanner별 결과와 전체 결과
6. 동일 종목 반복 선정 수와 교체율

**수용 기준**

- 미래 데이터로 당시 순위를 다시 쓰지 않는다.
- 동일 입력에서 순위가 100% 재현된다.
- 상장폐지 또는 데이터 중단 종목을 조용히 제외하지 않고 검열 건수로 기록한다.
- 결과를 수익 보장 통계로 표현하지 않는다 (§1.3).

### 범위 외로 이동한 항목

| 항목 | v1.3 | v1.6 |
|---|---|---|
| 분류별 가격 신호 확산 (구 P0-06) | P0 | P2 |
| 가상 포지션 추적 (구 P0-08) | P0 | **코드 없음. 스프레드시트 1장으로 운영** |
| 전향 검증 (구 P0-09 후반) | P0 | P1 |
| 사후 평가 자동화 (구 P0-10) | P0 | P1 |

가상 포지션은 후보 3개를 주 1회 갱신하는 작업이다. 손실 단계는 -10% / -20% 2단계로 축소하고, 각 단계의 행동을 스프레드시트에 문자로 적는다. -20%에서 신규 가상 진입을 중단한다.

## 7. 데이터 계약

### 7.1 공통 키

```text
instrument_id         내부 불변 식별자
source                KRX | KIWOOM_KR
source_instrument_id  소스 원본 코드
observation_date      Asia/Seoul 기준 거래일
date_status           TRADING | NON_TRADING | PUBLISH_PENDING | PARTIAL | FETCH_FAIL
fetched_at_utc        수집 시각
data_version          변환 규칙 버전
raw_sha256            원본 해시
```

서버 날짜나 수집 시각을 거래일로 사용하지 않는다.

### 7.2 가격과 부호

키움 응답의 가격 필드에 붙는 부호는 가격의 음수가 아니라 전일 대비 방향 표기일 수 있다. `pred_pre_sig`가 별도 필드로 존재하는 점에 유의한다.

- 필드별 계약에 따라 방향과 절댓값을 분리한다.
- 음수 가격을 그대로 저장하지 않는다.
- 원본 문자열을 별도 보존한다.

### 7.3 결측과 중단 상태

```text
MISSING_FIELD
EMPTY_STRING
REAL_ZERO
NON_TRADING_DAY
PUBLISH_PENDING
PARTIAL_SOURCE
FETCH_FAIL
DELISTED_OR_UNAVAILABLE
```

앞의 셋은 종목 단위, `NON_TRADING_DAY`와 `PUBLISH_PENDING`은 날짜 단위다. 같은 상태값을 공유하지 않는다.

성과 평가에서 사라진 종목을 조용히 제외하지 않는다. 4주 또는 8주 종료가격을 얻지 못하면 검열 건수로 기록하고 성과 집계의 분모를 함께 표시한다.

## 8. 데이터 품질·재현성 원칙

1. **원본 보존** — 인증정보를 제거한 원본과 해시를 보관한다.
2. **필드 단위 출처** — 마스터·가격·순자산총액의 출처를 각각 추적한다.
3. **시간 분리** — 관측 기준일, 수집 시각, 신호 생성·승인 시각을 구분한다.
4. **결측 유지** — §7.3의 8개 상태를 구분한다.
5. **기준 일치** — 가격 소스 대조 시 날짜·거래 세션·조정 여부를 맞춘다.
6. **급변 플래그** — 전일 대비 ±30% 이상 변화는 자동 점검 대상으로 처리하고, 분할·병합으로 자동 확정하지 않는다. **분배락 규모는 이 플래그로 잡히지 않으므로 §5.2를 별도로 적용한다.**
7. **불변 기록** — 기존 후보·평가 입력을 덮어쓰지 않는다.
8. **비밀정보 보호** — API 키·토큰은 서버에서만 관리한다.
9. **배포 경계** — 데이터 공개·재배포 기능을 만들지 않는다.

## 15. 최종 수용 기준

- 동일 원본·기준일·규칙 버전에서 유니버스와 순위가 100% 재현된다.
- 국내 선정은 KRX 거래대금을 사용하며, 문서와 코드의 계약이 일치한다.
- 현재 메타데이터가 과거 재현에 섞이지 않는다.
- 비거래일, 게시 지연, 부분 결측, 호출 실패를 구분한다.
- 검증되지 않은 필드가 필터·점수에 사용되지 않는다.
- 품질 Gate 실패 시 후보 발행이 차단된다.
- 관찰 후보를 억지로 3개까지 채우지 않는다.
- 가격수익률을 총수익률로 표현하지 않는다.
- 분배락 의심 건에 자동 가격 보정을 하지 않는다.
- 상장폐지 또는 데이터 중단 종목의 사후 성과를 조용히 제외하지 않는다.
- 과거 재현 결과를 수익 보장 통계로 표현하지 않는다.
