## 1. 제품 정의

**한 문장 정의**
MVP v0.2는 '전 산업을 자동으로 추천하는 서비스'가 아니라, **Core 6의 산업 근거·ETF 적합성·위험 규칙을 같은 시점의 데이터로 고정하고 가상 성과를 재현하는 내부 투자 의사결정 도구**다.

**배경 (v0.1 → v0.2)**
v0.1은 장기 제품 로드맵으로는 타당하지만 8주 MVP로는 과도했다. 8개 화면, 다중 역할 승인, 전 산업 실물지표 자동화, 100점 점수 모델을 8주에 동시에 구현할 수 없었고, 개발 기간(8주) 안에 1·3·6개월 투자 성과를 판정할 수도 없었다. v0.2는 기능의 약 50%를 후속 단계로 이관하고, **개발 완료(8주)와 투자 유효성 검증(12주 전향 관찰)을 명시적으로 분리**한다.

**반드시 증명할 4개 가설**
1. **데이터 가설** — 공식 또는 사용 권한이 확인된 데이터로 Core 6과 ETF 12~18개를 반복 갱신할 수 있다.
2. **운영 가설** — 운영자가 하루 30분·주 2시간 이내로 오류 확인·Radar 검토·가이드 발행을 수행할 수 있다.
3. **의사결정 가설** — 모든 발행 가이드가 근거 기준일·ETF 적합성·최대 비중·손절·무효화 조건을 누락 없이 가진다.
4. **검증 가설** — 같은 입력과 규칙 버전이면 같은 결과가 재현되고, 미래정보 없이 사후성과를 계산할 수 있다.

## 2. 사용자와 사용 시나리오

**페르소나**

| 역할 | 투입 | 책임 |
| --- | --- | --- |
| 투자 운영자 (1인) | 주 20시간 | 배치 감시, ETF 매핑, 가이드 발행, 가상 포지션 관리 |
| 투자 검토자 (1인) | 주 2시간 | 산업 태그, ETF 적합성 검토, 가이드 승인 |

MVP는 공개 사용자·자동매매·다중 역할을 대상으로 하지 않는다.

**대표 시나리오**

- **일일** — Data Status에서 배치 결과·결측·수동 보완 필요 항목 확인 → 재실행 또는 CSV 업로드.
- **주간** — Sector Board에서 Shadow Radar 후보 검토 → 근거·반대 근거 확인 후 보류/검토/승인.
- **월간** — Core 6 게이트 통과 산업에 대해 조건부 투자 가이드 발행 → 스냅샷 고정.
- **사후** — Guide & Paper에서 가상 포지션 진입·종료 및 벤치마크 대비 성과·최대낙폭(MDD) 평가.

## 3. 스코프

### 3.1 In-scope (MVP)

- **산업군**: Core 6 고정 실행군 + Shadow Radar 6~10개 관찰군
- **자산**: 국내 상장 ETF 12~18개 (일반형 중심, 레버리지는 별도 취급)
- **화면**: 4개 내부 화면 (§4)
- **기능**: P0-01~10 (§5.1)
- **의사결정 규칙**: 5개 게이트(G0~G4) + 10점 실험 점수 (§5.2)
- **주기**: 거래일 종가 후 데이터 갱신 / 주간 Radar 검토 / 월간 가이드 발행

### 3.2 Out-of-scope (MVP 비범위)

- 수익률 우월성의 통계적 입증, 6개월 성과 완료 판정
- 모든 산업의 자동 경기판단
- 리포트 원문 대량 저장·재배포
- 투자자문 자동 생성, 공개 사용자 가입·결제
- 실시간 시세·호가·체결, 증권사 주문 연동, 자동 리밸런싱
- 미국 ETF, 개별주 추천
- 전 산업 재무모델, 복잡한 다중 에이전트 운영

### 3.3 후속(P1/후속 단계)

| 항목 | 판정 | 사유 |
| --- | --- | --- |
| 전 산업 실물·거시지표 자동 연결 | 후속 | 산업별 품목 매핑·기준일 정합성 부담이 8주 초과 |
| 리포트 원문 자동 저장 | 축소 | MVP에서는 메타데이터·링크·해시만 |
| 호가 스프레드 자동 수집 | 후속 | 데이터 계약 확보 전에는 거래대금·순자산으로 대체 |
| 리포트 감성 자동 판정 | 삭제 | 제목 기반 방향성 판단 오류가 큼. MVP는 수동 승인 |
| 100점 스코어링 모델 | 대체 | 5개 게이트 + 10점 실험 점수로 축소 |
| 다중 역할 RLS·승인 워크플로 | 후속 | 단일 관리자 로그인 + 발행 스냅샷 우선 |
| LLM 예외 분류·서술 | P1 | 핵심 흐름 안정화 이후 제한적으로 도입, 점수 계산에는 사용하지 않음 |
| 자동매매·증권사 연동 | 제외 | 별도 제품 수준 |

| --- | --- | --- |
| **P0-01** | 데이터 소스 레지스트리 | 출처 · 필드 · 주기 · 권한 · 대체 경로 저장 |
| **P0-02** | 리포트 메타데이터 수집 | 중복 · 실패 · 변경 이력 확인 가능 |

| **P0-06** | 중복·위험 예산 | 기존 보유와 ETF 구성 중복 · 레버리지 합산 |

| **P0-08** | 불변 스냅샷 | 가이드 · 입력 · 규칙 버전을 동일 시점으로 고정 |
| **P0-09** | 가상 포트폴리오 | 종가 기준 가상 체결, 벤치마크 · MDD 계산 |

> P0 ID는 이후 ROADMAP과 이슈 트래킹의 참조 앵커로 사용한다. **재사용 시 ID를 재배정하지 않는다**.

### 5.2 의사결정 규칙 요구사항

**5개 게이트 (자동 점수보다 먼저 적용)**

| 게이트 | 통과 기준 | 실패 시 |
| --- | --- | --- |
| **G0** 데이터 품질 | 기준일·출처·결측·중복 상태가 허용 범위 | 점수 계산 및 가이드 발행 차단 |
| **G1** 산업 근거 | 리포트 활동 + 최소 1개 객관지표 또는 승인된 산업 이벤트 | 관망 |
| **G2** 가격 확인 | 산업 ETF/대표 바스켓의 상대강도 또는 추세가 논리와 모순되지 않음 | 신규 매수 보류 |
| **G3** ETF 적합성 | 기초지수·구성·유동성·비용·중복 검토 통과 | 대체 ETF 또는 산업 보류 |
| **G4** 위험 예산 | 기존 보유 중복·레버리지·산업 비중을 합산해 상한 이내 | 비중 축소 또는 매수 금지 |

**Shadow Radar 10점 실험 점수** (후보 정렬용, 임계값은 12주 검증 후 확정)

| 항목 | 점수 | 계산 방식 |
| --- | --- | --- |
| 리포트 활동 증가 | 0~3 | 최근 4주 건수의 과거 기준 대비 변화. 제목 감성은 미사용 |
| 증권사 확산 | 0~2 | 서로 다른 증권사 수와 집중도 |
| 가격 확인 | 0~2 | 관련 ETF/대표 바스켓의 KOSPI 대비 상대강도 |
| 객관지표 확인 | 0~3 | 승인된 산업 지표 최대 2개, 기준일과 방향 기록 |
| 과열·집중 감점 | 0 ~ −2 | 단기 급등, 단일 종목 의존, ETF 부적합 |

초기 상태 규칙: 0~3 관찰 / 4~5 검토 / 6점 이상 ETF 조사. **가상 편입은 7점 이상이더라도 G0~G4 통과 + 사람 승인 시에만 허용**.

### 5.3 투자 가이드 필수 출력

| 필드 | 필수 내용 |
| --- | --- |
| 최종 판단 | 매수 / 관망 / 비중 축소 |
| 근거 분리 | 확인 사실 / 계산 결과 / 해석·가정 / 반대 근거 |
| 위험 예산 | 전체·산업·ETF·레버리지 최대 비중과 기존 보유 중복 |
| 실행 규칙 | 분할매수 조건, 손절, 1·2차 목표, 무효화, 재검토일 |

**필수 필드가 하나라도 누락되면 가이드 발행 자체를 차단한다 (P0-07).**

## 6. 성공 지표 (2단계 분리)

### 6.1 8주 MVP KPI — 개발 완료 판정

| 범주 | 지표 | 통과 기준 |
| --- | --- | --- |
| 데이터 | 필수 필드 완전성 | 98% 이상, 결측은 상태값 |
| 수집 | 거래일 배치 성공 | 10거래일 연속 95% 이상 |
| 중복 | 리포트 중복률 | 1% 이하 또는 전건 검토 가능 |
| 분류 | Core 6 라벨셋 | 300건 이상 + 오류 유형 리포트 |
| 재현성 | 동일 입력·규칙의 동일 결과 | 100% |
| 추적성 | 가이드의 출처·기준일·버전 연결 | 100% |
| 운영성 | 일일/주간 수작업 시간 | 30분/일, 2시간/주 이내 |
| 안전 | 필수 위험 필드 누락 발행 | 0건 |
| 제품 | 대표 E2E | Data → Sector → ETF → Guide → Paper 전 구간 |

### 6.2 12주 전향 검증 KPI — 투자 효용 판정 (출시 후)

- 벤치마크 대비 상대성과와 최대낙폭을 **모두** 기록. **수익률 달성을 개발 완료 조건으로 삼지 않는다.**
- 가상 포지션별 손절·무효화 규칙 준수율, 과열 추격, ETF 매핑 오류, 신호 지연을 분리 측정.
- Shadow Radar 정밀도(실제 검토 가치가 있었던 후보 비율)와 운영자 승인률.
- 레버리지 ETF는 일반형과 분리해 보유기간·낙폭·변동성 손실을 별도 평가.

### 6.3 판정 매트릭스

| 판정 | 조건 | 다음 조치 |
| --- | --- | --- |
| **Go** | 데이터·재현성·운영성·안전 KPI 모두 통과 | 12주 전향 검증 시작 |
| **조건부 Go** | Core 6 가이드 동작, Shadow Radar 정밀도 낮음 | Radar 매매 권한 없이 Core-only 운영 |
| **재작업** | 특정 지표·ETF 구성 데이터만 불안정 | 수동 입력으로 대체 후 2~4주 재검증 |
| **No-Go** | 데이터 권한/기준일 확보 실패 또는 결과 재현 불가 | 웹 확장 중단, 데이터 설계부터 재검토 |

**중요**: 12주 결과가 좋더라도 통계적 우월성을 확정하지 않는다. '계속 운영할 가치가 있는가'와 '손실 통제가 작동하는가'를 판정하는 단계다.

## 7. 일정 요약

총 20주 구성: **8주 개발 + 12주 전향 검증**. 개발자 주 20시간·검토자 주 2시간 가정. 데이터 소스 계약이 1주차에 확정되지 않거나 개발자 투입이 주 15시간 미만이면 10~12주로 재조정한다.

**개발 마일스톤**

- **W1** 데이터 스파이크 → **1주차 Go/No-Go 게이트** (미통과 시 웹 개발 중단, 데이터 계약·수동 업로드로 범위 재확정)
- **W2** 저장·수집 (스키마, 리포트 메타, ETF 가격, job log)
- **W3** 분류·Radar (Core 6 사전, 300건 라벨셋, 활동·확산·가격 신호)
- **W4** ETF 비교 (마스터·구성 스냅샷, 집중도·중복도·레버리지 구분)
- **W5** 가이드 (G0~G4, 3개 시나리오, 필수 필드 강제, 스냅샷)
- **W6** 가상 포트폴리오 + 4개 화면 통합
- **W7** 제한적 과거 재생 (가용 데이터만 as-of, 미래정보 누수 사례 기록)
- **W8** 안정화·UAT (10거래일 운영 리허설) → **8주차 Go / 조건부 Go / No-Go 판정**

**검증 마일스톤 (출시 후)**

- **W1~4** Shadow Radar만 관찰, 실제 매수 가이드는 Core 6 중심
- **W5~8** 조건 충족 후보 가상 편입, 임계값 고정
- **W9~12** 동일 규칙 유지, 실패 유형 누적 → **v1.0 승격 또는 점수 폐기·재설계 판정**

> 주차별 상세 작업 목록, 인력 배분, 검증 운영 규칙은 `docs/ROADMAP.md`에서 관리한다(별도 문서).

## 8. 데이터 원칙

**원칙**

1. **공식 또는 사용 권한이 확인된 데이터만 사용**한다. API 존재가 상업적 재배포·대량 수집 권한을 의미하지 않는다.
2. **as-of 스냅샷 기준**으로 저장한다. 발표일 이후 가격만 사용하고, 수정된 지표는 별도 버전으로 관리한다.
3. **결측은 상태값으로 보존**한다. 0으로 대체하지 않는다.
4. **산업별 객관지표는 최대 2개**로 제한하며, 과거 기준일 재현이 불가능한 지표는 백테스트 입력에서 제외한다.
5. **CSV 수동 업로드 경로**를 모든 자동 수집 소스에 대해 대체 경로로 준비한다.

**주요 데이터 소스 (2026-08-19 기준, 실제 구현 직전 재확인)**

- KRX Data Marketplace — ETF 기본·시세
- 한국은행 ECOS Open API — 거시지표
- 금융감독원 Open DART — 공시
- 네이버 금융 산업분석 — 리포트 메타데이터

**MVP 데이터 처리 요약**

| 데이터 | 수집 | 갱신 | 실패 시 대체 |
| --- | --- | --- | --- |
| 산업 리포트 | 제목·업종·증권사·일자·링크·해시 | 거래일 | 승인된 CSV 수동 업로드 |
| ETF 마스터/가격 | 공식/사용 허가 데이터 | 가격 일별 / 마스터 주별 | KRX·운용사 CSV |
| ETF 구성종목 | 12~18개 공식 스냅샷 | 주 1회 | 운용사 파일 수동 등록 |
| Core 6 객관지표 | 산업당 1~2개 | 월/발표일 | 공식 발표값 수동 입력 |
| 보유 포트폴리오 | 종목·수량·평균가·레버리지 CSV | 변경 시 | 화면 직접 입력 |
| 리포트 라벨셋 | 제목 300건+ 사람 태깅 | 초기/분기 | Core 6 우선 표본 |

> 상세 스키마(테이블·필드·관계)와 간소화 아키텍처는 `docs/architecture.md`로 이관한다(별도 갱신).

| 운영자 편향 | 발행 후 불변 스냅샷, 반대 근거 필수 | 승인 판단의 주관성 |

## 10. 착수 전 확정 필요 결정 (Open Questions)

착수 전 아래 항목을 확정한다. 미확정 항목은 1주차 데이터 스파이크 결과와 함께 재검토한다.

- [ ] ETF 후보 12~18개와 일반형 / 집중형 / 밸류체인형 / 레버리지형 분류
- [ ] KRX · 운용사 · 리포트 메타데이터의 실제 접근 방식과 이용조건
- [ ] Core 6별 객관지표 1~2개와 발표 기준일 · 품목 매핑
- [ ] 사용자 보유 ETF를 CSV로 입력할지, 초기에는 가상 포트폴리오만 사용할지
- [ ] 일반 ETF와 레버리지 ETF의 최대 비중 · 보유기간 · 손절 상한
- [ ] Shadow Radar 초기 후보 6~10개와 제목 300건 라벨 담당자
- [ ] 개발자 주 20시간 · 투자 검토자 주 2시간의 실제 확보 여부
